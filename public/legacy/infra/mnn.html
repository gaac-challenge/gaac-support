MNN

阿里巴巴开源的端侧推理引擎,MNN-LLM 让大模型在手机上跑

与主线一 KV cache · 中手机上的 KV 分层:内存不够时把 KV 写到闪存,并支持前缀 KV 落盘与 KV 量化与主线二 Agent 负载 · 弱支持工具调用模板和本地 API 服务,但未见端侧 agent 的规模化使用证据

它是什么

MNN(Mobile Neural Network)是阿里巴巴开源的深度学习推理引擎,主要跑在手机和嵌入式设备上。它最初是为淘宝 App 里的图像识别、推荐、直播特效这类小模型服务的;2023 年以后,团队在它之上做了 MNN-LLM,把大语言模型也搬到手机上,并发布了面向普通用户的示例应用 MNN Chat。

对第一次听说它的读者,可以这样定位:llama.cpp 是社区做的、从 PC 和 Mac 起家的本地引擎;MNN 是大厂做的、从手机起家的端侧引擎,对 Arm CPU、手机 GPU 和 NPU(神经网络处理器)的适配更深,也是图里唯一来自中国的端侧运行时。

它做了什么

通用推理引擎

MNN 能把 TensorFlow、Caffe、ONNX、TorchScript 模型转换成自己的格式,在多种后端上执行:CPU(x86、Armv7/v8/v9 含 SME2、RISC-V RVV)、GPU(OpenCL、Vulkan、Metal、CUDA)、NPU(CoreML、高通 QNN 与 Hexagon、华为 HIAI、NNAPI 等)一手README。

MNN-LLM:导出、量化、运行

MNN-LLM 是建在引擎之上的大模型方案,分三步一手MNN LLM 文档:

  1. 导出:llmexport 工具把 Hugging Face 或 ModelScope 上的模型导出为 MNN 格式,支持合并或分离 LoRA 权重。
  2. 量化:默认 4 bit、块大小 64;可选 HQQ、AWQ、OmniQuant 等算法提高量化后精度,文档建议加 --hqq;也支持 2、3、8 bit 以及导入 GPTQ 权重。3.6.2 新增 --qat,可直接读取量化感知训练的检查点。
  3. 运行:通过一个 JSON 配置选择后端、线程数、精度和内存策略。

论文里讲的几项针对手机的设计一手,论文原文arXiv 2506.10443 HTML:

  • 内存与闪存混合存储:词嵌入表每次解码只读一行,整张表放到闪存上,作者估算 Qwen-7B 可省约 2.18 GB 内存。
  • 按硬件重排数据:根据 CPU 指令集(如 Arm i8mm)和 GPU 特性重新排列权重布局。
  • 多核负载均衡:手机 CPU 有大小核,按各核实测能力分配任务。

论文自报的性能:在小米 14 上用 4 线程 CPU 跑 Qwen2 等模型,prefill 比 llama.cpp 快 8.6 倍、解码快 2.3 倍;OpenCL GPU 上 prefill 最高快 25.3 倍厂商自述;单一设备,解码只测 16 个 token,对比的是 2024 年的 llama.cpp,无独立复现。

MNN Chat

MNN Chat 是开源的手机应用,模型完全在设备上运行,支持文本、图像、语音输入和扩散模型生图,内置模型市场、基准测试页和本地 API 服务;最新 Android 版为 0.8.3一手MNN Chat README。

2026 年的现状

  • 截至 2026-11-18,GitHub star 16,572、fork 2,540,当天仍有提交一手GitHub API。
  • 3.6.2(2026-10-29)的数字属实。发布说明原文:Qwen3.5-2B 在 iPad Pro M5 的 GPU 上通过 Metal 后端运行,Prefill 3542.91 tok/s;启用 DFlash 后 Decode 从 111.89 提升到 233.98 tok/s,为常规解码的 2.09 倍厂商自述;一手读到原文。DFlash 是一种投机解码方案,用草稿模型一次起草多个 token 再由目标模型验证;发布说明没有给出量化配置和提示词长度MNN releases。
  • 3.6.1 新增直接编程的高通 Hexagon NPU 后端:Qwen3-0.6B 在骁龙 8 Elite 上 prefill 2667 tok/s,为 CPU 的 7.9 倍厂商自述。
  • 2026 年的其他方向:Qwen3.5 的线性注意力算子、MoE、2 到 3 bit 权重量化、RISC-V(进迭时空 K3)、摩尔线程 MUSA、Rockchip NPU。
  • 竞争位置:端侧面对 Meta 的 ExecuTorch、Google 的 LiteRT 和社区的 llama.cpp。MNN 的特点是紧跟 Qwen 系列,并覆盖国产芯片。

与主线一(KV cache)的关系

关系为中等,比预想的要实。报告的主线一讲的是数据中心里 KV cache 从显存扩展到内存、SSD、网络;MNN 在手机这个尺度上做了同一件事的缩小版,而且写进了论文和配置项。

  • KV 溢出到闪存:论文描述 KV cache 先放在内存,超过阈值后把多出的部分搬到闪存,并在当前层的 MLP 计算和下一层的 QKV 投影期间预取,以掩盖读盘延迟一手,论文原文arXiv 2506.10443 HTML。对应的配置项是 kvcache_mmap(默认关闭)和 tmp_path(磁盘缓存目录)一手MNN LLM 文档。
  • 多轮复用:reuse_kv 控制多轮对话是否复用之前的 KV,默认关闭。3.5.0 新增文本级别的 Prompt Cache,用于加速多轮对话的首 token一手MNN releases。
  • 前缀 KV 落盘:接口 setPrefixCacheFile 把公共前缀的 KV 存成文件。文档中的 rollback_demo 说明:第一次启动把前缀的 KV 写入磁盘,第二次启动跳过这段 prefill 直接加载;3.6.2 把这一能力扩展到 OpenCL 后端,并修复了按后端与精度隔离缓存文件的问题。同一示例还演示用 eraseHistory 删除不需要的 KV 片段、只保留相关部分。
  • KV 量化:attention_mode 可选把 key 和 value 量化为 int8(文档称精度几乎无损),或用 3.5.0 引入的 TurboQuant TQ3/TQ4 压到 3 至 4 bit(文档称内存节省 30% 以上,建议只用于 40 亿参数以上的模型,小模型损失较大)厂商自述。

与数据中心的差别在于目的:这里没有多租户和跨节点路由,落盘是为了在几个 GB 内存的手机上不被系统杀掉,以及让 App 冷启动后不必重算固定的系统提示词。它不涉及网络存储,也不存在 KV 在设备之间共享。

与主线二(Agent 负载)的关系

关系偏弱。能核实到的只有能力层面的支持:

  • 聊天模板在 3.5.0 迁移到 Jinja,模型目录下的 context.json 可以声明 tools,消息支持 tool 角色和带 tool_calls 的 assistant 消息一手MNN LLM 文档。
  • MNN Chat 提供本地 API 服务,更新记录提到改进了对 Anthropic 协议的兼容一手MNN Chat README。
  • MNN-Pocket-0.3B 的定位是手机 App 内的任务模型,前缀 KV 落盘也适合"固定系统提示词加工具定义"这类 agent 式的重复前缀。

但本次没有找到 MNN 被用于端侧 agent 或本地 coding agent 的公开案例,也没有找到阿里系 App 在生产中用 MNN-LLM 跑 agent 的一手说明。它出现在图里,不是因为与 agent 主线关系强,而是因为它代表了中国的端侧推理路线:报告把端侧格局概括为三大厂商栈加 llama.cpp 与 MLC 两条社区线,再加中国的 MNN。

与图中其他概念的关系

  • llama.cpp:同属本地与端侧阵营;MNN-LLM 论文以它为对比基线,MNN 的基准工具 llm_bench 的 -pg 参数明确对齐 llama-bench 的语义。
  • GGUF:MNN 使用自己的模型格式,不读 GGUF;两者是并行的端侧量化产物。
  • EAGLE-3:MNN 支持 Eagle 系列投机解码,3.6.1 修复过影响 Eagle3 输出质量的 KV 索引错误。
  • ExecuTorch、LiteRT:端侧运行时的直接竞争者。
  • llm-compressor:无直接关系;MNN 自带量化流程,但可导入 GPTQ 权重。
  • 数据中心侧的 vLLM、SGLang、Dynamo、Mooncake 等,以及网关层各概念:无直接关系。

存疑与未核实

  • 报告称 MNN 3.6.2 的数字出现在"iPad Pro M5 上"。核实无误,更准确的说法是 M5 的 Metal GPU 后端;这是项目自测,未说明量化配置。
  • 笔记把 MNN-LLM 论文记为"arXiv 2025-06"。arXiv 上传日期确是 2025-06-12,但论文实际发表于 MMAsia 2024 Workshops,性能对比反映的是 2024 年的状态;"最高 8.6 倍"具体指小米 14 上 CPU prefill 相对 llama.cpp。
  • MNN-LLM 在淘宝、钉钉等阿里 App 中的具体使用情况未能核实。README 的"30 多个 App、70 多个场景"是针对 MNN 整体的旧表述,不能当作大模型落地的证据。
  • 论文里关于闪存预取可掩盖多长 KV 的具体数字,抓取结果的单位有疑问,本文未引用。
  • 文本级 Prompt Cache 的实现细节(是否跨进程持久化)没有在文档中找到说明。
  • MNN-Pocket-0.3B 的性能数字只见于 README 与二手报道,未读其技术报告。
