Cerebras

把整片晶圆做成一颗芯片、主打每秒上千 token 输出的推理芯片与云公司

与主线一 KV cache · 中KV cache 与权重挤在每片 44GB 的片上 SRAM 里,容量直接决定并发数与长上下文成本与主线二 Agent 负载 · 强把高速输出卖给编码 agent:Codex-Spark、Cerebras Code 均以此为卖点

它是什么

Cerebras Systems 是一家美国 AI 芯片公司,总部在加州 Sunnyvale,2026 年 5 月在纳斯达克上市(代码 CBRS)。它的产品有三层:一颗叫"晶圆级引擎"(Wafer-Scale Engine,WSE)的芯片;装着这颗芯片的整机 CS-3 / CS-4;以及用这些整机搭起来、按 token 收费的推理云 Cerebras Inference。

普通芯片的做法是在一片 300 毫米晶圆上刻出几十上百颗芯片,再切开分别封装。Cerebras 不切:整片晶圆就是一颗芯片。现役的 WSE-3 用台积电 5nm 工艺,有 4 万亿个晶体管、90 万个计算核心和 44GB 片上 SRAM一手WSE-3 发布新闻稿。SRAM 是速度最快的一类存储器,通常只在处理器里做小容量缓存;GPU 的模型权重放在芯片外的 HBM(高带宽内存)里。

它解决的问题是"单个用户拿到 token 的速度"。大模型每生成一个 token,都要把用到的权重从内存读一遍,所以输出速度主要受内存带宽限制,而不是算力。WSE-3 把权重直接放在紧挨计算核心的 SRAM 里,招股书给出的内存带宽是 21 PB/s,并称比 NVIDIA B200 封装高 2625 倍厂商自述424B4 招股书。结果是公开目录里的模型标称速度在每秒 1850–3000 token厂商自述模型目录,而 GPU 上同类模型通常是每秒几十到一两百。

它做了什么

晶圆级芯片为什么快,代价是什么

快的原因有两条。第一,权重在片上 SRAM 里,读取带宽比片外 HBM 高几个数量级。第二,整片晶圆内部的核心用片上连线互通,不需要像多 GPU 那样经过板级网络。

代价主要是容量。SRAM 每比特占的面积远大于 DRAM,一整片晶圆只有 44GB,还不如一张高端 GPU 的显存。Cerebras 官方博客用约 3 万亿参数的 Kimi K3 举例说明怎么办:权重做 4 bit 量化后每层约 16GB,把模型按层切开摆到多片晶圆上串成流水线,层间只传激活值(走以太网 RDMA,每跳约 2 微秒)。这个例子一共需要 59 片晶圆厂商自述,示意性算例How Cerebras Deploys Trillion-Parameter AI Models。也就是说,一个前沿模型的一份副本就要占掉几十台整机。

其他代价:

  • 模型支持窄:共享云目录目前只有 gpt-oss-120b 和 qwen-3.8-27b 两个模型;更多模型(GLM、Kimi、DeepSeek V3.x、Llama、Mistral 等)只在预留容量的 Dedicated Inference 里提供一手(模型目录)Dedicated Inference 文档。模型要经过 Cerebras 自己的编译器映射到晶圆上,不能直接跑 vLLM 之类的通用引擎。
  • 上下文长度:两个共享模型的付费档上下文是 131k / 128k token,免费档减半一手(模型目录)。
  • 功耗与成本:第三方分析称新一代 CS-4 机柜功耗 125–135 kW(CS-3 为 23 kW),每瓦性能至多略好于上一代二手SemiAnalysis。

与主线一(KV cache)的关系

关系中等,而且是以"约束"的形式出现。

KV cache 放在哪:官方博客写明,每个全注意力层要为每个在途请求的每个 token 保存 key 和 value,这些数据放在承载该层的晶圆的片上 SRAM 里,与权重共用 44GB。Kimi K3 的算例因此让每片晶圆只放一个全注意力层(约 16GB),剩下约 28GB 留给 KV cache;线性注意力层只需固定大小的状态,一片能放两层。博客的结论是:分给 KV cache 的片上内存决定最大并发请求数厂商自述(部署博客)。

对长上下文意味着什么:上下文越长,每个请求占的 SRAM 越多,同一批晶圆能同时服务的用户就越少。SemiAnalysis 估算,以 100 万 token 上下文运行 1.6 万亿参数的 DeepSeek V4 Pro 需要约 20 套系统,并预计客户会用 256k 而非 1M 上下文来节省片上 KV 开销二手,部分内容付费墙后未读到(SemiAnalysis)。报告主线一讲的是 KV cache 从显存向主机内存、SSD、网络存储分层外溢;Cerebras 的生成路径上没有这种便宜的下层可用,它的应对是加晶圆,或把 KV cache 量化到 8 bit(算例中的假设)。

前缀缓存:Cerebras 提供 prompt caching,自动生效,按 128 token 分块做前缀匹配,保证存活 5 分钟、最长 1 小时,可用 prompt_cache_key 把同一会话路由到同一份缓存。文档称缓存"只在内存中、不持久化",存放在与模型实例同一数据中心的键值存储里。命中的 token 不打折,仍按标准输入价计费,好处是降低首 token 延迟,并且不计入"未缓存 token"限速额度一手Prompt Caching 文档。这与多数 GPU 云对缓存命中大幅折价的做法不同。文档没有说明这个键值存储在晶圆上还是在主机内存里。

分离式推理:第三季度财报称已推出"异构分离式推理"厂商自述;SemiAnalysis 的解读是让带 HBM 的芯片(AWS Trainium、AMD)承担需要大内存的部分,Cerebras 负责解码二手。如果属实,KV 数据就需要在两类芯片之间搬运,但公开材料没有给出机制。

与主线二(Agent 负载)的关系

关系强,而且是公司的主要定位。

  • OpenAI 的第一个落地模型是 GPT-5.3-Codex-Spark(2026-02-12 研究预览),一个为快速推理优化的小号 Codex,运行在 Cerebras 上,速度超过每秒 1000 token。Cerebras 的说法是:agent 自主工作数小时会让开发者"脱离回路",高速模型让人能实时插手调整一手,厂商自述Codex-Spark 博客。
  • 机制上,agent 的一个任务是"生成 → 调工具 → 再生成"的几十上百轮循环,总耗时约等于各轮生成时间之和加工具耗时。输出快 10 倍以上,循环里模型这一段就近似消失。官方《Designing for Cerebras》文档据此建议把 LLM 调用当同步函数调用、取消任务队列和逐步进度展示一手Designing for Cerebras。
  • 文档的集成列表以 agent 框架和编码工具为主(Cline、OpenCode、Kilo Code、Aider、CrewAI、LangGraph、Browser-Use 等)一手文档索引。
  • 矛盾之处:agent 负载同时意味着长上下文和高度重复的前缀,这正好压在上一节的 SRAM 容量约束上。速度对 agent 有利,长会话的 KV 占用对 Cerebras 不利,两者同时成立。
