Agent 质量基准:排版、深度调查与财务预测

三类都无现成基准可照搬;规则检查加二元清单评审,门槛按同一 agent 的官方 API 参照线定

先说结论

比赛的 Agent Bench 要回答的问题只有一个:选手的推理栈有没有把模型弄坏。它不需要回答"哪个 agent 更强"。这一点决定了后面所有选择,也是它与公开基准最大的不同:公开基准比的是系统之间的高低,我们要的是同一个 agent 换了推理后端之后的"不劣于"判定。

调研下来有五个判断:

  1. 三类任务都没有可以整套照搬的基准,但每一类都有可以拆下来用的零件:排版用 PresentBench 的逐题二元清单加 SlidesGen-Bench 的可计算指标;深度调查直接复用团队已有的规则手册、评审细则和计分程序;财务预测拆成"分析正确性"(Finance Agent 的做法)和"预测"(FutureX、FinDeepForecast 的一周窗口)两半。
  2. 评审方式上业界在 2026 年已基本收敛:整体打 1–5 分或 0–10 分的做法与人的一致性差,逐条二元判定明显更好;单一评委换成三家模型的评委组;能用程序查的不交给模型。
  3. MLPerf 的"99% 精度门槛"不能直接套。它依赖几千到几万条确定性样本,而 agent 任务每类只有几十到一两百条,抽样噪声就有几个百分点。门槛要写成"带容差的不劣于检验",容差由参照线自己的重复运行波动决定。
  4. 财务预测在一周内无法用"预测准不准"区分队伍。公开数据里,99 道题分不开职业预测者和最好的机器人。一周内能做的是:分析部分查对错,预测部分与参照线比一致性,结果揭晓后的 Brier 分数只作事后公布。
  5. 推理优化确实会伤 agent 质量,而且平均分常常看不出来。量化对工具调用的影响因模型大小而异;上下文压缩有掉 25–34 个百分点的报告;同一权重在不同服务商之间的工具调用差异,主因是工具调用解析器而不是量化。

几个值得细看的做法

PPTEval 是被引用最多的整体打分法,也是被后来者批评最多的。 它与人评的皮尔逊相关系数为内容 0.70、设计 0.90、连贯性 0.55;标注者是 4 名研究生,评了 250 套,标注者之间的一致性(Fleiss Kappa)平均 0.59一手,同上。两篇 2026 年的论文用各自的人评数据重测,结论都是它与人的排序相关性偏低:PresentBench 报告的斯皮尔曼相关为自己 0.532、PPTEval 0.303,人与人之间为 0.664(样本只有 24 个);SlidesGen-Bench 报告自己 0.71、PPTAgent 评法 0.53、直接让模型打分 0.57、人与人 0.85一手,均为作者自测。两篇都是提出新方法的论文,数字对自己有利是预期之中的,但方向一致:整体打分不如逐条判定,也不如可计算指标。

PresentBench 的清单结构可以直接借。五个维度里,前两个(基础、视觉版式)与素材无关,后三个(完整、正确、忠实)要对照输入素材。每条清单是一个只能答"满足"或"违反"的问题,要求给出证据位置(第几页)。维度得分是满足条数的占比,总分是五个维度的简单平均。评审前把 PPTX 转成 PDF,评审模型看到的是渲染后的页面;超出题目页数上限的部分直接截掉一手。它用的评审模型是 gemini-3-flash-preview,论文没有报告评审成本。

**SlidesGen-Bench 的可编辑性指标(PEI)**是目前唯一把"能不能编辑"量化的做法。它解析文件结构,分 L0 到 L5 六级:L0 整页是图片,L1 文字可编辑,L2 有矢量形状,L3 用了母版和组合,L4 有原生参数化图表,L5 有动画和切换;低一级不过,高一级不计分。PPTX 用 python-pptx 和 Office Open XML 解析一手。这一项对我们有直接用处:它能挡住"把整页渲染成一张图塞进 PPTX"这种取巧。

Paper2Poster 的 PaperQuiz给"内容有没有传达到"提供了一个不靠打分的量法:由模型根据论文出 100 道选择题(50 道照原文、50 道要理解),让 6 个读者模型只看海报作答,正确率再乘一个长度惩罚系数,防止把全文搬上去一手。SlidesGen-Bench 的内容分也是同一思路,每份素材 10 道题。

可程序化检查的部分

溢出和重叠是排版任务最常见的硬伤,但上表没有一个基准把它做成独立的规则指标。PPTAgent 论文自己在局限里承认,生成结果会出现元素重叠一手;Paper2Poster 的生成系统靠一个 VLM 看局部放大图来判"溢出、太空、可以了",是生成环节的自检,不是评测指标一手。

这里有一个工程事实需要先知道:PPTX 文件里存的是文本框的位置和大小,不存文字实际排出来占多大。文字是否溢出取决于字体、字号、行距和渲染器,只读 XML 判断不了,必须渲染之后比较。我们的判断,未找到公开基准验证

几个指标的精确定义:

  • Brier 分数:预测概率与结果(0 或 1)之差的平方,对所有题取平均。越低越好,永远报 0.5 得 0.25。Prophet Arena 是先在一个事件的各个市场内平均,再对事件平均一手。
  • Brier 指数:(1 − Brier 分数的平方根)× 100%。永远报 0.5 得 50%,完全正确得 100%。2026-03 时超级预测者为 70.6%,最好的模型为 67.9%一手FRI 说明。
  • FutureX 的数值题得分:max(0, 1 − ((真值 − 预测)/σ)²),σ 是该指标此前 7 天的标准差;偏离超过一个标准差得零分一手。
  • FinDeepForecast 的数值题容差:百万量级的财务指标相对误差 5% 以内算对,百分比和比率类 1%,利率和汇率 0.1%。最好的系统总正确率 39.5%;其中数值类最高只有 25.5%,二元事件类最高 81.4%一手。

预测类评测的三个特殊问题

第一,等结果。 上表中最短的周期是一周(FutureX、FinDeepForecast),这是可行的下限。

第二,回测会泄漏。 把时间拨回去让模型预测已发生的事,看似解决了等待问题,实际上漏洞很多。一项对谷歌日期过滤搜索的审计用了 393 道已结算的 Metaculus 题目:71.0% 的题目至少搜到一个含有截止日期之后重要信息的页面,41.0% 的题目至少搜到一个直接给出答案的页面;只用无泄漏文档时 Brier 为 0.242,混入泄漏文档后降到 0.108–0.129。泄漏途径有四种:页面事后更新、侧栏的相关文章、"某权威来源没提这件事"本身构成信号、时间戳不可靠。作者的建议是用冻结的、带时间戳的网页快照一手时间泄漏审计。另一篇方法论文章指出更隐蔽的"逻辑泄漏":回测题目本身是在知道结果之后挑的;并建议用模型的发布日期而不是自称的知识截止日期作上界,再留几个月余量一手Pitfalls 论文。

第三,样本量不够分辨。 Metaculus 2026 年春季锦标赛持续三个多月,机器人与职业预测者有 99 道共同题目,机器人队的两两对比得分为 −1.25,95% 置信区间 −4.87 到 2.37,不显著(单侧 p = 0.247)二手,同上。Prophet Arena 上 23 个模型的 Brier 分数挤在 0.18–0.22 之间,市场基线是 0.187一手。一周、几十到一两百道题,不可能用 Brier 分数把七支用同一个模型的队伍分开。

2026 年有一篇论文认为自我偏好近九成可归因于评委的不确定性,更像测量假象仅摘要EMNLP 2026 Findings。结论有争议,但不影响对策:避开同源评委没有成本。

门槛:绝对线还是相对线

MLPerf Inference 是"先质量后效率"最成熟的先例。它的做法是相对线:封闭组的每个基准规定质量目标为参考精度的 99% 或 99.9%,不达标则性能结果无效。现行规则里与我们相关的几行:

基准 样本数 质量目标 附加条件

Llama3.1-405B 8,313 FP16 参考的 99% 每样本 token 数须在参考的 90%–110% 之间
DeepSeek-R1 4,388 FP16 参考的 99%(精确匹配 81.9132%) —

一手MLPerf Inference 规则原文。同一份规则还明确禁止缓存查询和响应,允许"任何能达到质量目标的量化方案",但要求方法公开、可复现。

有两点值得借,一点不能照搬:

  • 值得借:生成长度约束。 只卡精度的话,选手可以压低输出上限或砍掉推理 token 来换速度。MLPerf 用"token 数不低于参考的 90%"堵这个口子。
  • 值得借:重复运行。 GPT-OSS-120B 那一行对每个数据集重复多次再合计,是对采样波动的直接处理。
  • 不能照搬:99% 这个数字。 它建立在几千到几万条确定性判分的样本上。agent 任务若每类 100 题、成功率 70%,单次运行成功率的标准误约 4.6 个百分点,两次独立运行之差的标准误约 6.5 个百分点。1 个百分点的门槛在这个样本量下没有意义。我们的推算

AA-AgentPerf 也声明"用精度校验防止牺牲质量换容量",但页面没有写校验的具体做法(见 concepts/aa-agentperf.md),无从借鉴。

三点含义:

  1. 量化的风险集中在小模型和长上下文。上述量化研究用的几乎都是 10B 以下的模型,比赛用的是大得多的模型,结论不能直接外推,只说明要测。
  2. "通过率不变"不等于"行为不变"。重试变多意味着任务完成时间和成本变差,这恰好会体现在效率六项里。质量门槛之外,应当记录每个任务的调用轮数和工具调用格式错误数。
  3. 最容易出事的是聊天模板和工具调用解析器,而不是量化位宽。选手自选推理框架,这一层各家实现不同,应作为单独的预检项。

对我们做 Benchmark 的启发

总原则:测的是推理栈,不是 agent

每一类都用同一套流程:同一个 agent、同一批题、同样的工具和语料,只换推理后端。后端 A 是 DeepSeek 官方 API(参照线),后端 B 是选手的系统。这样 agent 设计得好坏在两边抵消,剩下的差异才归因于推理栈。前提是 agent 由主办方固定,或者选手的 agent 冻结后先对着官方 API 跑一遍。plans/plan-autodl-4gpu.md 里"选手真实 agent"一档属于后一种,需要在规则里写明参照线由谁、在何时跑。

质量门槛怎么定

  1. 参照线跑多次。 同一 agent 对官方 API 至少跑 5 次,得到每类任务成功率和清单符合率的均值与标准差。这一步同时量出了"官方 API 自己有多不稳"。
  2. 门槛写成不劣于检验。 选手成绩不低于参照线均值减去容差即过。容差取"参照线 2 倍标准差"与一个预先写定的下限(建议 5 个百分点)中较大的一个。题量按能分辨 10 个百分点的下降来定,每类不少于 100 个可程序判分的任务。
  3. 硬伤单列,不参与平均。 编造来源、文件打不开、输出格式不合规这类,规定一个绝对上限(例如不超过参照线的发生率加 2 个百分点)。
  4. 加长度约束。 仿照 MLPerf,每任务输出 token 数和调用轮数须在参照线的一定范围内(建议 90%–150%),防止靠截短输出或砍推理换速度,也能暴露"重试变多"。
  5. 所有阈值在看到任何队伍成绩之前写定。 这一条沿用团队方案第四阶段的做法。

绝对线只建议用在硬检查上。成功率、清单符合率这类指标用相对线,因为题目难度是我们自己定的,没有外部标尺。

一周赛程内财务预测怎么评

分三层,只有前两层进门槛:

  • 第一层,分析正确性(当场判)。 题目形如"根据所给财报和行情快照,算出某指标并预测下季度区间"。抽取和计算部分有标准答案,按 Finance Agent 的检查点方式判,数值容差沿用 FinDeepForecast 的分档。
  • 第二层,预测一致性(当场判)。 同一题让参照线和选手系统各跑多次,比较两边预测值或概率的分布:均值之差、选手均值是否落在参照线的波动范围内。这回答的是"推理栈有没有改变模型的判断",不需要等结果。
  • 第三层,预测准确性(事后公布,不进门槛)。 每队比赛周的周一出一批一周内揭晓的题(财报披露、宏观数据发布、收盘价区间),周日结算,算 Brier 分数和容差内正确率。因为七队各在不同的周,题目不同,只报"选手相对同周参照线的差",不做跨队比较。

资料一律用主办方冻结的带时间戳快照,不给实时搜索,这同时满足出网管控和防泄漏。题目的揭晓日期必须晚于模型发布日期,最好留出几个月。

评审报告 Agent 应该输出什么

每个任务一条记录,每队一份汇总:

  • 标识:队伍、任务编号、题目校验值、agent 版本、推理后端配置的哈希、评委型号与版本、运行时间。
  • 硬检查结果:逐项通过与否,不过的附机器可读的原因(第几页、哪个元素、溢出多少)。
  • 程序计分:各项原始值。
  • 评审判定:逐条清单的判定、每位评委的原始票、是否有分歧、证据位置(页码或报告原文引句)。
  • 与参照线的对比:参照线均值和波动范围、选手数值、差值及置信区间、是否过门槛。
  • 失败归类:超时、报错、格式不合规、工具调用格式错误、内容错误、编造来源。
  • 过程量:调用轮数、工具调用次数与格式错误数、输入输出 token 数。这些直接交给效率六项。
  • 待人工复核清单:评委分歧项、离门槛最近的判定、全部硬伤判定。
  • 可复算包:原始产出、渲染图、存档网页、评委提示词与原始输出,保证第三方能重算。

存疑与未核实

  • 比赛指定模型与参照线是否同一个模型。DeepSeek 官方定价页当前列出的是 deepseek-flash(V4.1-Flash-1017)和 deepseek-v4-pro(V4-Pro-0813),上下文 1M,并有峰谷两档价格一手DeepSeek 定价页。方案草稿按"671B 级满血 DeepSeek"估算显存。如果选手本地跑的开放权重与官方 API 背后的模型不是同一版,质量差异里就混入了模型差异,"不劣于参照线"会失去意义。这一点需要先拍板。另外峰谷价差一倍,会影响"每成功任务成本"的对标口径。
  • 量化对工具调用的研究几乎都基于 10B 以下模型,对大型 MoE 模型在 FP8 或 4-bit 浮点下的 agent 质量,没有找到公开的对照研究。
  • PresentBench 与 SlidesGen-Bench 的"与人一致性优于 PPTEval"均为作者自测,样本分别只有 24 个和未在可读部分说明的规模,没有第三方复现。
  • SlidesGen-Bench 的 PEI 具体判定条件在附录 K,本次未读到;PresentBench 未见公开的代码仓库许可。
  • ForecastBench 对未结算的市场题如何计分、难度调整的具体算法,官方文档页和 wiki 都没有写明,要看技术报告;批评其指数跨期不可比的文章The copier line本次抓取失败,只见到搜索摘要。
  • Metaculus FutureEval 的方法页返回 403,相关数字来自其工作人员在 LessWrong 的结果帖。
  • PPTC、Mind2Web 2、DeepResearchGym、GAIA、FinBen 以及评审偏差的几篇论文只读了摘要或搜索摘要;GAIA 的当前最高分各来源相互矛盾,没有采用。
  • "溢出必须渲染后才能判""每类不少于 100 题""容差 5 个百分点""长度范围 90%–150%"是本文的工程判断和建议值,没有公开先例直接支持,需要用参照线的实测波动来校准。
  • 未发现与《LLM 推理基础设施全景》报告或已有概念文档相矛盾之处。报告称 MLPerf v6.1 新增 RAG 与边缘 agentic 测试,本次读到的规则主干分支未专门核对这两项。
