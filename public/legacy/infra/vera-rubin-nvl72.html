Vera Rubin NVL72

NVIDIA 继 Blackwell 之后的 72 GPU 液冷整机架系统

与主线一 KV cache · 强每 GPU 288 GB HBM4 存活跃 KV,另配 BlueField-4 的 CMX 闪存层与主线二 Agent 负载 · 强厂商以 agentic AI 定位整机与 Vera CPU,已有 AA-AgentPerf 实测

它是什么

Vera Rubin NVL72 是 NVIDIA 卖给云厂商和 AI 实验室的一整个液冷机架,是 Blackwell 一代 GB200/GB300 NVL72 的继任者。名字拆开看:

  • Vera 是 NVIDIA 自研的 Arm 架构 CPU,88 个定制 Olympus 核心一手。
  • Rubin 是新一代 GPU,官方给出的推理算力是每颗 50 petaFLOPS(NVFP4,一种 4 比特浮点格式)厂商自述。
  • NVL72 指 72 颗 GPU 通过 NVLink(NVIDIA 私有的 GPU 间高速互连)连成一个域,软件可以把整个机架当成一台大机器用。

所以它不是一块显卡,而是交付单位为「机架」的整机:72 颗 Rubin GPU、36 颗 Vera CPU、NVLink 6 交换、ConnectX-9 网卡和 BlueField-4 DPU(数据处理器,一种带独立处理器的智能网卡)装在一起出厂 NVIDIA CES 新闻稿。它解决的问题是:大模型推理和训练需要很多 GPU 紧密协作,把互连、供电、液冷在工厂里预先集成,比客户自己用单台服务器拼集群更快上线。

它做了什么

机架里有什么

NVIDIA 产品页给出的单机架规格厂商自述产品页:

项目 数值
GPU 72 颗 Rubin
CPU 36 颗 Vera(共 3,168 核)
GPU 显存(HBM4) 20.7 TB,带宽 1,400 TB/s
CPU 内存(LPDDR5X) 最高 54 TB
NVFP4 推理算力 3,600 PFLOPS
NVLink 6 带宽 216 TB/s

HBM(高带宽内存)是堆叠封装在 GPU 旁边的显存;20.7 TB 即 72 × 288 GB。Artificial Analysis 的对比表显示,Rubin 每 GPU 的 HBM 容量与 GB300 相同(288 GB),变化在带宽:19.2 TB/s 对 8 TB/s;Vera 与 GPU 之间的 NVLink-C2C 链路为 1.8 TB/s,是上一代的两倍一手,第三方整理的厂商规格Artificial Analysis。机架功耗 NVIDIA 产品页没有写,二手来源给出约 190–230 kW,互不一致二手,仅摘要Hashrate Index。

「每 token 成本十分之一」是怎么测的

CES 新闻稿正文只写「相对 Blackwell 平台,推理 token 成本最多降低 10 倍,训练 MoE 模型所需 GPU 减为四分之一」,没有脚注。测试条件写在产品页脚注里:模型是 Kimi-K2-Thinking,输入 32K token、输出 8K token,比较对象是 GB200 NVL72(不是更新的 GB300),并注明「可能变更」;「四分之一 GPU」是对一个 10 万亿参数 MoE 模型的推算值厂商自述产品页。媒体标题里的「推理性能 5 倍」对应的是单 GPU 峰值算力的代际比较,本次没能读到 Tom's Hardware 正文(抓取被截断),只能按标题引用仅摘要Tom's Hardware。

与 Groq LPX 的搭配

LPX 机架装 256 颗 Groq 3 LPU(源自 NVIDIA 与 Groq 的技术授权交易),共 128 GB 片上 SRAM。NVIDIA 的说法是 Rubin GPU 与 LPU「共同计算每个输出 token 的每一层」来加速解码,搭配后每兆瓦吞吐最高 35 倍;产品页脚注注明这是推算值,场景是万亿参数模型、最多 40 万 token 已缓存上下文的高价档位,基线未写明厂商自述GTC 新闻稿。8 月财报称 LPX「已全面量产」一手。

2026 年的现状

独立程度较高的数字有两组。

MLPerf v6.1(封闭组,preview 类别):NVIDIA 自报 Vera Rubin NVL72 相对 GB300 NVL72,在 Qwen3-VL 上吞吐最高 3.7 倍(vLLM + Dynamo),在 DeepSeek-R1 上最高 2.5 倍(TensorRT-LLM);提交方只有 NVIDIA 与 Nebius厂商自述,基于经审核的提交NVIDIA blog。preview 类别意味着硬件尚未普遍可得,不能与 available 类别直接排名。同一篇博客还说在 SemiAnalysis 的 AgentX 上「预览测试 30 倍于 GB300」,没有给任何配置条件,且 AgentX 不属于 MLPerf厂商自述。

AA-AgentPerf(2026-10-15):在 DeepSeek V4 Pro 上,Rubin 的每兆瓦吞吐领先 GB300 最多约 5.7 倍(每用户约 190 tok/s 的高速档),但在峰值吞吐点只领先 1.14 倍;Rubin 的首 token 时间更长(约 165 tok/s 档中位 1.65 秒对 1.08 秒),若把首 token 等待计入端到端速度,GB300 在该模型的多数速度档持平或反超。配置由 NVIDIA 提供,功耗只计 GPU 与 HBM,不含 CPU、网络和冷却一手Artificial Analysis。也就是说,「5 倍」量级的优势出现在高交互速度区间,而不是全区间。

路线图(GTC 2026 主题演讲,经 The Next Platform 整理):2027 年 Rubin Ultra 配 Kyber 机架,单机架 144 个 GPU 插槽;2028 年 Feynman,配 Rosa CPU、LP40 LPU 与带共封装光学的 NVLink 8。每插槽 1 TB HBM4E、最多 1,152 GPU 的域规模等数字是该文作者的估算,不是 NVIDIA 公布值二手The Next Platform。

竞争位置:AMD 在 Helios 发布时直接拿 Vera Rubin NVL72 作靶子,用的正是同一个 Kimi K2 Thinking 32K/8K 负载 AMD 新闻稿。

与主线一(KV cache)的关系

关系强,而且是平台设计的一部分。按 NVIDIA 生态的分层叫法(经 NAND Research 整理)二手NAND Research:

  1. G1,GPU 的 HBM:活跃 KV 所在。每 GPU 288 GB、每机架 20.7 TB。这一代容量没有比 GB300 增加,增加的是带宽(约 2.4 倍),所以 Rubin 对 KV 的直接贡献是「读写更快」而不是「装得更多」。
  2. G2,主机内存:每机架最高 54 TB LPDDR5X,经 1.8 TB/s 的 NVLink-C2C 与 GPU 相连。AA-AgentPerf 的 Rubin 配置明确用了「KV cache 卸载到主机内存」。
  3. G3,节点本地 SSD。
  4. G3.5,CMX:CES 上叫 Inference Context Memory Storage,GTC 起作为 BlueField-4 STX 参考架构的首个机架级实现,称 CMX。它是 pod(若干机架组成的单元)内共享的以太网闪存层:BlueField-4 在硬件里管理 KV 块的放置,经 Spectrum-X 以太网用 RDMA 访问,Dynamo 负责在各层之间搬运上下文,NIXL 负责 KV 块传输一手NVIDIA newsroom。新闻稿的原话是「KV cache 不能长期存放在 GPU 上」。
  5. G4,企业共享存储:毫秒级延迟,不适合活跃上下文。

需要保留的判断:CMX「相对传统存储最高 5 倍 tokens/s」是厂商自述,新闻稿没有说明基线配置;NVIDIA 8 月财报只提到 STX 的安全特性,没有 CMX 的出货表述;NAND Research 明确说没有独立基准,并提示存储厂商对 NVIDIA 路线图的依赖。HBM 供给方面,SK hynix 在 2026-10-28 的财报会上称 DRAM 与 HBM 供给到 2029 年基本售罄仅摘要,这是 Rubin 产能的外部约束。CXL(一种内存扩展互连标准)在本次读到的 NVIDIA Rubin 材料中没有出现,NVIDIA 走的是 LPDDR5X 加以太网闪存层的路线。

与主线二(Agent 负载)的关系

关系强,但强在定位和基准,而不是「硬件为 agent 做了某个专用电路」。

  • 厂商原话:产品页标题是「Rack-Scale Agentic AI Supercomputer」,并称 agentic 系统消耗的 token 最高是传统应用的 15 倍;CES 新闻稿称 Vera CPU「为 agentic reasoning 设计」;GTC 新闻稿标题就是「Vera Rubin Opens Agentic AI Frontier」厂商自述。
  • CPU 需求:GTC 上单独推出 256 颗 Vera 的 CPU 机架,理由是「强化学习与 agentic AI 负载依赖大量基于 CPU 的环境来测试和验证」;2026-05-31 的新闻稿进一步写明 CPU 位于「agent 工具调用与沙箱执行」的关键路径上,自称任务完成速度为 x86 的 1.8 倍(未说明负载),并称 Anthropic「正在评估」用 Vera 扩展 CPU 密集的 agentic 负载厂商自述NVIDIA newsroom。
  • 基准:MLPerf v6.1 新增的 agentic 测试是边缘项(单用户设备回放 SWE-bench 轨迹),NVIDIA 用 Jetson 提交,与 Rubin 机架无关;数据中心侧的 agentic 测量要等后续的 MLPerf Endpoints。真正在 agent 负载上测了 Rubin 的是 AA-AgentPerf:回放真实 coding agent 轨迹,输入 token 平均 97% 与上一请求重复,即高度依赖前缀缓存一手。注意那篇 Rubin 文章报告的是每兆瓦 token 吞吐,没有直接给 Agents per Megawatt 数值。

与图中其他概念的关系

  • Dynamo:NVIDIA 的推理编排框架。Rubin 的 MLPerf 与 AA-AgentPerf 提交都用它做 prefill/decode 分离与会话感知路由,它也是 CMX 的上层调度者。
  • vLLM、TensorRT-LLM:Rubin 两类提交各自使用的引擎(Qwen3-VL 用 vLLM,DeepSeek-R1 用 TensorRT-LLM)。
  • AA-AgentPerf:已测 Rubin,见上。
  • AMD Helios:直接竞品,规格与宣传都以 Rubin 为对照。
  • TPU Ironwood:Google 既自研 TPU,也是 Rubin 的首批云客户(A5X 裸金属实例)Google Cloud blog。
  • Mooncake:与 Dynamo/NIXL 同属 KV 传输与分层方案,InfoQ 在介绍 Google TPU Sync 时把它们并列为 GPU 侧替代品二手。
  • Cerebras:Groq LPX 的加入让 NVIDIA 平台内部有了与 Cerebras 同类的低延迟推理硬件。
  • 昇腾:NVIDIA 的业绩指引假设中国数据中心算力收入为零,Rubin 与昇腾实际上分属两个市场。

存疑与未核实

  • 报告写「10 倍」相对 Blackwell,未注明基线是 GB200 而非 GB300;以产品页脚注为准。
  • 报告称「StorageReview 标题写每加速器 5.7 倍」并把它当作 Rubin 的倍数之一。StorageReview 正文显示 5.7 倍是 MLCommons 统计的 DeepSeek-R1 服务器场景最佳单加速器成绩相对一年前 v5.1 的提升,不是 Rubin 对 GB300 的数字 StorageReview。碰巧 AA-AgentPerf 里也有一个「约 5.7 倍」,两者无关。
  • NVLink 机架带宽:CES 新闻稿写 260 TB/s,产品页写 216 TB/s,未能解释差异。
  • 本文没有直接读 MLCommons 结果表,Rubin 的绝对吞吐数字未核实;一篇二手分析称按 Nebius 表格折算的单 GPU 提升约 1.6–2 倍仅摘要。
  • 出货量、机架单价、机架功耗均无一手数字。笔记中「7 月 21 日已向 OpenAI 出货」的说法只有单一低质量来源,未能核实。
  • HPCwire 的路线图文章返回 403,未读到;Kyber 的 600 kW 等数字本文未复核。
  • CMX 是否已在生产环境出货未获确认;ServeTheHome 报道在 OCP 2026 上看到实机仅摘要。
