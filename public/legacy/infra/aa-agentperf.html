AA-AgentPerf

回放真实编程 agent 轨迹,测硬件每兆瓦能同时服务多少 agent

与主线一 KV cache · 中允许并依赖 KV 复用:历史轮次走缓存,缓存做得好坏直接体现在分数里与主线二 Agent 负载 · 强把基准的负载和计量单位都从请求和 token 换成了 agent 会话

它是什么

AA-AgentPerf 是独立评测机构 Artificial Analysis 于 2026-06-12 发布的一个硬件推理基准。它不发固定长度的合成请求,而是回放真实的编程 agent 工作轨迹,不断加大并发,找出一套系统在每个 agent 都还"够快"的前提下最多能同时撑住多少个 agent。首要指标是 Agents per Megawatt(每兆瓦可服务的并发 agent 数)一手AA-AgentPerf 文章。

它要回答的问题是数据中心采购方真正关心的那个:电力是硬约束,一兆瓦电能支撑多少个同时干活的 agent。传统基准报告的"每秒多少 token"答不了这个问题,因为 agent 的请求长短悬殊、大部分输入是重复的历史,token 吞吐和"能服务多少用户"之间不是简单换算。

来历与时间线

Artificial Analysis 是一家总部在旧金山的独立 AI 评测公司,另在墨尔本设有办公室,联合创始人为 Micah Hill-Smith(CEO)与 George Cameron(CPO)。它自称"the independent benchmarking company for AI",评测对象包括 agent、模型、托管模型的云端点和芯片;官网称已评测 500 多个模型、100 多家推理供应商、1000 多个端点。公开列出的出资人有 Nat Friedman、Daniel Gross、Andrew Ng、Adam D'Angelo、Clem Delangue、Guillermo Rauch 等个人投资者一手,公司自述Artificial Analysis About。行业里它最为人熟知的是模型的 Intelligence Index 和各家 API 端点的速度、价格对比。成立年份和融资金额该页面没有写,本次未核实。

  • 2026-06-12:发布 AA-AgentPerf,自称"第一个 agentic 推理基准",此前与推理供应商、加速器厂商、企业买家合作了一年;页面标注为"Live benchmark,开放提交"。
  • 首发只有一个模型(DeepSeek V4 Pro,推理强度 max)和四套系统;预告了 gpt-oss-120b。
  • 之后滚动更新:方法论页的模型设置里已出现更多模型(例如提到 Muse Spark Open 用 xhigh 推理强度),说明覆盖面在首发后扩大,但当前完整结果表我没能打开。

它做了什么

负载:真实轨迹

轨迹在开源的 OpenCode agent 框架里生成:让三个开启推理的开放权重模型(DeepSeek V3.2、GLM 4.7、Kimi K2.5)去解决真实公开代码仓库的 issue,记录下完整的多轮过程。一段会话最多 200 轮,累计可超过 10 万 token;单次请求的输入长度从约 5 千到约 13.1 万 token,平均约 2.7 万;输出多数是很短的工具调用和代码编辑(中位数约 150 token),偶尔有长段推理。覆盖 12 种以上编程语言,Python 最多。厂商可拿到 500 条轨迹(18,997 个 prompt)的调优子集,完整测试集保密,防止针对性优化一手方法论页。

回放方式

每个模拟 agent 顺序走完一条轨迹。每次工具调用之后插入一段固定延迟,按工具类型从真实工具执行时长里采样,范围从 0.1 秒以下到 5 秒,中位约 1 秒,用来模拟"模型在等工具返回"。max_tokens 设为 16K 以防复读循环拖歪结果(同上)。

找容量

在一组固定的并发档位上逐档测量。每一档要满足:至少完成 30 条轨迹、每个 agent 至少完成 3 条、稳态时间至少 10 分钟;只统计所有 agent 都已在目标并发下活跃 30 秒以上的时段。文章描述的搜索方式是先指数加倍直到指标破线,再二分找最大并发。

服务目标(SLO)

"够快"的标准来自 Artificial Analysis 自己对市面上 serverless API 的测速数据,即市场上真实存在的服务档位。按请求统计两项:P25 输出速度(四分之三的请求要快于它)和 P95 首 token 时间(TTFT)。文章给出的 DeepSeek V4 Pro 三档是 20、60、180 token/秒,对应 P95 TTFT 不超过 10、5、3 秒;每套系统在每一档都出一个结果一手AA-AgentPerf 文章。

功率与归一化

功率是测试过程中实测的加速器功率(GPU 芯片加 HBM 显存),不是标称 TDP,也不含 CPU、网络和散热。所以"每兆瓦"指的是每兆瓦加速器实耗功率,不是每兆瓦机房供电。结果同时按每加速器、每系统、每兆瓦、每美元小时租金归一化;租金取自 Silicon Data,缺数据的芯片用 AA 自己的估计(方法论页)。

允许什么

允许生产中真实会用的优化:KV cache 复用、投机解码(speculative decoding)、prefill 与 decode 分离部署;用精度校验防止靠牺牲输出质量换容量,校验的具体做法页面没有写。厂商可以提交为自家系统调优的完整配置,由 Artificial Analysis 运行和验证,配置全文随结果公开。

首发结果

被测系统是 NVIDIA GB300 NVL72(整机柜)、NVIDIA B300 八卡、NVIDIA H200 八卡、AMD MI355X 八卡。B300 和 GB300 的配置由 NVIDIA 提交;H200 和 MI355X 因为没有厂商提交,由 Artificial Analysis 自己搭。文章明说:每套系统都还有"数量不等的余量",自建的两套余量可能更大,AMD 上针对该模型的内核优化尚处早期。定性结论是 Blackwell 相对 Hopper 有明显代际提升,整机柜因规模和更激进的分离部署而在每兆瓦指标上领先一手AA-AgentPerf 文章。

具体数值我只从 NVIDIA 的博客读到:GB300 NVL72 为每兆瓦 6.14 万个并发 agent、每 GPU 57.5 个,H200 为每兆瓦 2600 个、每 GPU 1.4 个,NVIDIA 概括为"每兆瓦并发 agent 数高至 20 倍"厂商自述,转述 AA 结果;条件为 DeepSeek V4 Pro、30 token/秒档,且 H200 配置并非厂商调优NVIDIA 开发者博客。

三者的共同方向是:被测对象从"芯片加模型"变成"整套服务栈",允许生产优化,用真实多轮轨迹。AA-AgentPerf 的独特之处是直接以 agent 为计量单位,并用市场上的真实服务档位定 SLO;弱点是测试集和校验方法不公开,外人无法复现,功率也只算加速器。

AA 预告的后续:上下文扩到 100 万 token、更多模型与加速器架构、把执行工具调用的 CPU 性能纳入、以及"每美元租金的 agent 容量、每任务成本、TCO"等经济指标。

与主线一(KV cache)的关系

关系中等。AA-AgentPerf 本身不是 KV cache 技术,但它是第一批把 KV 复用写进规则、让缓存做得好坏直接进分数的基准。

  • 负载结构决定了缓存的权重:agent 每一轮的输入是"全部历史加一点新内容"。平均 2.7 万 token 的输入对应中位约 150 token 的输出,如果每轮都从头预填充,系统绝大部分算力花在重算历史上。文章明确说历史轮次由 KV cache 提供,只有新增 token 需要预填充。
  • 缓存不许作弊:每个并发档位开始时,基准在每条轨迹开头加一段动态生成的前缀,使上一档留下的缓存全部失效。这样测到的是会话内的正常复用,而不是跨测试阶段的残留命中。
  • 计量口径:报告的输入吞吐包含从 KV cache 提供的 prompt token,所以缓存命中率高的系统,输入吞吐数字会很大。读数时要留意这一点。
  • 间接推动存储层级:并发 agent 越多,需要同时保留的会话 KV 越多,显存放不下就要么驱逐后重算,要么下沉到主机内存或 SSD。基准没有规定怎么做,也没有披露各配置的 KV 存放位置;它只是让这个选择的后果体现在"能撑多少 agent"上。计划中的 100 万 token 上下文会进一步放大这一点。

与主线二(Agent 负载)的关系

关系强,它就是主线二在度量层面的直接产物。

  • 负载单位变了:被模拟的不是独立请求,而是一个顺序走完整条轨迹、中间夹着工具等待的 agent。请求之间有依赖、有共同前缀、有思考间隔。
  • 计量单位变了:为什么从 token 转向 agent?文章给的理由是,固定输入输出长度的合成请求加上关闭生产优化,永远回答不了"一套系统能以可接受的体验服务多少个 agent"。再补一层机制上的解释:在 agent 负载里,大量输入 token 来自缓存、成本极低,少量输出 token 才是瓶颈,把两者加在一起的"token 每秒"既不反映成本也不反映用户体验;而"在给定速度和首 token 时间下的并发 agent 数"直接对应可售卖的席位数。这层解释是我的归纳,不是 AA 原话。
  • 约束变了:SLO 的 TTFT 上限给到 3 至 10 秒,比聊天场景宽松,因为等待的是程序而不是人;但输出速度下限按档位严格要求,因为 agent 一个任务要连续跑上百轮,单轮慢会被放大。

与图中其他概念的关系

  • Vera Rubin NVL72:首发测的是上一代 GB300 NVL72。NVIDIA 在博客里预期 Rubin 会延续优势,但那是前瞻说法,不是 AA-AgentPerf 的实测。
  • AMD Helios:首发测了 AMD 的 MI355X 八卡节点,由 AA 自建配置;Helios 整机柜是否已提交,本次未查到。
  • TPU Ironwood、Cerebras、昇腾:AA 说会加入"更多加速器架构",首发文章里没有这些系统。
  • vLLM、SGLang、TensorRT-LLM:NVIDIA 博客称其提交使用了这类运行时,并靠跨整个机柜的专家并行(WideEP、DeepEP)和 MoE 内核优化取得结果厂商自述。推理框架及其版本是配置披露的一部分,所以这个基准同时也是引擎调优水平的比拼。
  • Dynamo:NVIDIA 博客的标签里有 Dynamo,正文没有说明它在提交中的作用,不作断言。
  • OpenRouter:OpenRouter 的平台数据(agent 占 token 的 76%)是这类基准存在的需求侧理由;AA 的 SLO 档位则取自它对各家 API 端点的测速数据。两者没有合作关系。
  • EAGLE-3:投机解码被明确列为允许的优化,但各配置具体用了哪种方法,我没有读到。

存疑与未核实

  • SLO 档位数值不一致:AA 文章写 DeepSeek V4 Pro 三档为 20、60、180 token/秒;NVIDIA 博客的表格写 30、100、300 token/秒,同一篇博客的图注又提到 20 和 60。AA 文章里也出现过 30、100、300 的示意数字。可能是档位在发布后调整过,也可能是抓取时混入了示意值。引用具体倍数时必须同时写明档位。
  • "每兆瓦"口径:只算加速器实测功率,不含 CPU、网络、散热。与 InferenceX 的机房供电口径不可直接比较,也不能直接当作机房规划数字。报告正文没有提到这一点,建议补上。
  • 20 倍这个数字:是 NVIDIA 调优配置对 AA 自建的 H200 配置,AA 自己提示后者余量更大;NVIDIA 博客的摘要与正文对"20 倍对应哪一档"的说法也不一致。
  • 各系统的官方数值表、当前在榜模型和系统清单:结果页我尝试的地址返回 404,未读到;文中数值只有 NVIDIA 转述的两套系统。
  • 精度校验方法、测试集总规模、KV 在各配置中的存放层级:来源均未披露。
  • InferenceX AgentX 的细节来自搜索摘要和一篇部分付费的文章,未读到完整方法论。
  • Artificial Analysis 的成立年份、融资额、收入模式:About 页未写,未核实。
