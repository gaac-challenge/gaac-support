截至 2026 年 11 月，LLM 推理基础设施的工作可以清晰地分为五层：推理引擎与运行时、模型压缩与编译、集群级服务与编排、硬件与算力、网关/生态/经济性；贯穿五层的两条主线是 KV cache 从显存内的数据结构变成跨显存、主机内存、SSD 与网络存储的独立层级，以及 agent 负载把服务单位从"请求"改成"程序/会话"。引擎层已收敛为 vLLM 与 SGLang 双寡头加 llama.cpp/Ollama/MLX 的本地阵营，TGI 已归档；模型层的生产标准是 FP8 近乎无损、4-bit 为性价比甜点，量化工具全部绑定到具体运行时；集群层由 llm-d 1.0（CNCF）与 NVIDIA Dynamo 1.0 两条路线定型，前缀/KV 感知路由是收益最确定的优化；硬件层以液冷整机架为交付单位，HBM 售罄使内存而非逻辑芯片成为最紧约束；接入层的网关与可观测性公司在 2026 年被支付、安全与数据平台收购，token 的用量加权有效价格继续下降，但前沿模型标价与中国 API 均价在上涨。各层共同的未决问题是：特性叠加后的正确性无人能穷举测试，厂商的性能与成本倍数互不可比，有状态的 agent 会话与无状态的弹性基础设施之间缺少跨层接口。需要提前说明的是，本报告所依据的笔记中，引擎版本与 release notes 多为一手来源，而硬件、融资、收入与大量基准数字来自二手媒体或厂商自述，下文逐处标注。

引擎层：vLLM 与 SGLang 双寡头成形，竞争从算法收敛到默认值与运维

格局已定：两家数据中心引擎、三家本地运行时，TGI 退场

数据中心 GPU 侧的开源引擎已是 vLLM 与 SGLang 两强。按 2026-11-17 的 GitHub API 快照，star 数为 ollama 187,427、llama.cpp 135,665、vLLM 97,113、SGLang 38,987、MLX 29,200、TensorRT-LLM 15,087、TGI 10,877（已归档）一手；star 只是采用度的代理指标，笔记未找到生产部署规模的一手数据vLLM APISGLang API。vLLM 最新稳定版 v0.34.0 于 2026-11-16 发布，含 "1,061 commits from 412 contributors"，全年保持约两周一个 minor 版本的节奏 vLLM v0.34.0；SGLang v0.5.23 于 2026-11-02 发布，含 "1007 PRs from 257 contributors" SGLang v0.5.23。两个项目都在 2026 年孵化出公司：Inferact（vLLM 维护者创立）1 月宣布 1.5 亿美元种子轮、估值 8 亿美元，RadixArk（SGLang）5 月宣布 1 亿美元种子轮、估值 4 亿美元，NVIDIA 与 AMD 参投二手，媒体报道TechCrunchSiliconANGLE。

曾经的主流 Hugging Face TGI 已退场：官方文档写明其进入维护模式并推荐 vLLM、SGLang、llama.cpp 与 MLX，GitHub 仓库已归档，最后一次 push 为 2026-03-21一手；"2025-12-11 进入维护模式"这一日期只见于二手来源TGI docsTGI API。与之对应，llama.cpp 背后的 ggml.ai 团队于 2026-02-20 宣布加入 Hugging Face二手Simon Willison。合起来看，Hugging Face 的策略已从"自己做服务端引擎"转为"掌握本地运行时"，这是笔记作者的推断而非官方表述。

NVIDIA 的 TensorRT-LLM 正在换底座。最新预发布 v1.4.0rc3（2026-11-06）的 breaking 项包含 "Remove obsolete TensorRT-backend compatibility surfaces"，并出现 PyTorchModelEngine 等条目，说明引擎主体已是 PyTorch 后端 TensorRT-LLM v1.4.0rc3。这里笔记之间存在不一致：压缩与编译方向的笔记依据二手文章仍把 TensorRT-LLM 描述为"提前编译引擎"的代表，而"何时去掉 engine 构建步骤"在二手来源中也互相矛盾；本报告以一手 release notes 为准，即它正从编译型引擎变为 NVIDIA 的 PyTorch 原生参考引擎，其 kernel（"TRTLLM-Gen MoE"等）被 vLLM 与 SGLang 直接复用 vLLM v0.34.0。

本地与端侧由 llama.cpp、Ollama、MLX 三家主导。Ollama 最新稳定版为 v0.40.16（2026-11-09），并在 Apple Silicon 上引入了 MLX 引擎；常被引用的 "58 → 112 tok/s" 对比同时更换了量化格式，不是纯引擎对比官方博客 + 二手Ollama releasesOllama blog。中国生态方面，阿里 MNN 3.6.2（2026-10-29）报告 Qwen3.5-2B 在 iPad Pro M5 上启用 DFlash 后 decode 从 111.89 提升到 233.98 tok/s（项目自测）MNN releases；上海 AI Lab 的 LMDeploy v0.18.0 新增昇腾支持 LMDeploy releases；华为昇腾有独立的 vllm-ascend 插件线 vllm-ascend；源自 Moonshot 与清华的 Mooncake 已作为 KV connector 进入 vLLM 主线 vLLM v0.34.0。MindIE、Xinference 以及百度、腾讯、字节自研引擎的 2026 年状况，笔记未取得一手来源。

运行时的增量集中在 KV 分层、投机解码与 MoE 专用路径

连续批处理、分页 KV、前缀缓存与 chunked prefill 已是所有引擎的基线，其学术源头是 Orca（OSDI 2022）、vLLM/PagedAttention（SOSP 2023）、Sarathi-Serve（OSDI 2024）与 SGLang 的 RadixAttention（NeurIPS 2024）公认文献，本轮未逐篇复核OrcaPagedAttentionSarathi-ServeSGLang。2026 年的增量有三处。

第一，KV 容量取代算力成为首要约束。vLLM v0.34.0 把 extensible KV cache 设为默认，按 warmup 后的实际空闲显存确定 KV 大小（MiniMax-M3 在 H200 上从 433k 增至 672k tokens），代价是部分模型在并发 128 时 TPOT 上升 6–18%；同时默认 block size 从 16 改为 64、gpu_memory_utilization 默认 1.0 vLLM v0.34.0。引擎愿意用延迟换缓存，这本身就是判断。KV 也不再只待在显存里：vLLM 有主机内存 offload 与 NIXL、Mooncake、LMCache 等 connector，SGLang 的 HiCache 支持文件型 L3 存储，NVIDIA Dynamo 文档列出 KVBM、LMCache、FlexKV、HiCache 四种 offload 后端 SGLang v0.5.23Dynamo KV offloading。"LMCache 在高命中负载上延迟降 3–10×"与"RadixAttention 把首 token 延迟降 50–80%"都只见于二手来源，没有一手基准。

第二，投机解码从可选加速变成随模型发布的配套件。vLLM v0.34.0 支持 draft model、ngram、EAGLE3、MTP、suffix decoding、DSpark、DFlash/DFlash2 等方法族并提供插件 API vLLM v0.34.0。DSpark、DFlash、HiSparse、KVCR 等名词笔记只从 release notes 条目得知其存在与效果数字，没有找到说明其机制的设计文档，故本报告不解释其原理。

第三，按模型家族定制。超大 MoE（vLLM release notes 称 Mistral Large 4 为 "1T total / 52B active"）、稀疏与压缩注意力（MLA、DSA）、混合状态空间模型都有专用 kernel 与并行模式（TP/PP/DP/EP 加上下文并行）；SGLang 的 Paged Experts 让超出显存的 MoE 在单张消费级 GPU 上运行，自称比 CPU offload 快至 30× SGLang v0.5.23。引擎的边界也在外扩：vLLM-Omni 把自回归运行时扩展到扩散模型与实时语音，SGLang 模型表出现 Diffusion 类别，TensorRT-LLM 加入文生视频管线 vLLM-Omni。需要注意，这些 "Diffusion" 均指图像/视频扩散，笔记没有找到任何引擎对文本扩散 LLM 的一手支持说明。

另有两个容易被忽视的方向。其一是每请求 CPU 开销：vLLM 把 128K prompt 的每请求 CPU 开销降了 40×，并维护 Rust 前端，说明 GPU kernel 足够快之后 Python 调度路径决定了高并发上限 vLLM v0.34.0。其二是结构化输出：XGrammar 论文称在 H100 上端到端最高 80× 加速 XGrammar，但 vLLM 论坛有用户反馈它在部分消费级 GPU 上因 CPU–GPU 同步反而比 Outlines 慢 vLLM forum。

引擎层的开放问题：组合爆炸下的静默错误比性能更现实

特性组合的正确性是引擎层最突出的未决问题。vLLM v0.34.0 的修复项包括 "DFlash acceptance of 0 with FULL CUDA graphs" 与 "grammar-invalid drafts"；TensorRT-LLM v1.4.0rc3 的 Known Issues 写明 DSA 模型使用 NVFP4 KV cache 时可能输出错误 TensorRT-LLM v1.4.0rc3。模型 × 硬件 × 并行模式 × 量化 × 投机解码 × KV 后端的测试矩阵已超出单一社区可穷举的范围，这解释了 batch invariance 等确定性特性为何在 vLLM 中逐 kernel 推进而仍未全覆盖。运维负担同样现实：v0.34.0 一次列出 8 项 breaking change。

基准不可比是第二个问题。二手博客的横评互相矛盾——一篇称 SGLang 与 LMDeploy 在 H100 上约 16,200 tok/s、vLLM 约 12,500 tok/s，另一篇给出 TensorRT-LLM 2,100 tok/s 对 SGLang 1,920 tok/s——硬件、模型、版本、流量形态各不相同二手，厂商相关博客PremAISpheron。本报告因此不给出"最快引擎"的结论。此外，这一节的"开放问题"是笔记从 release notes 与论坛归纳的，没有维护者路线图或综述作为权威出处；2026 年系统顶会的引擎层论文清单也未抓取，是这一层最大的资料缺口。

模型层：8-bit 近乎无损、4-bit 是甜点，压缩工具必须绑定运行时

量化的位宽阶梯清晰，格式由硬件代际决定

服务端的事实标准是 FP8（W8A8）加 INT4 权重量化（W4A16），工具链收敛到 vLLM 旗下的 llm-compressor；本地的事实标准是 llama.cpp 的 GGUF K-quant。最权威的精度数据来自两项评测。"Give Me BF16 or Give Me Death"?（ACL 2025）在 Llama-3.1 三个规模上做了 50 万次以上评测，结论是 FP8 基本无损、调优良好的 INT8 下降约 1–3%、INT4 权重量化接近 8-bit仅摘要arXiv 2411.02355。2026 年 1 月的 "Which Quantization Should I Use?" 在 Llama-3.1-8B 上统一评测 GGUF 格式，数据见下表一手，已读原文；局限是单模型、单 CPU 平台，约 1 分以内的差异可能是噪声arXiv 2601.14277。

2026 年的三个新变化值得单独说。其一，Blackwell 一代的 4-bit 浮点微缩放格式进入主线：NVIDIA 自报 NVFP4 达到 FP8 级精度厂商自述，仅摘要NVIDIA Research，但一份第三方 RTX 5090 测试显示 NVFP4 比 FP8 快约 30% 的同时 GSM8K 掉约 1.5 分，并提到部分消费级 Blackwell 上 NVFP4 GEMM 输出不正确的未关闭 issue单一第三方来源，仅摘要computingforgeeks。llm-compressor 的 README 给出超大模型实例：一个 MXFP4xFP8 检查点从约 1644 GB 降到约 428 GB，但没有给出精度恢复数字一手，README 原文；其中的模型名笔记作者无法独立核实llm-compressor。

其二，KV cache 量化成为独立议题，且风险在尾部。vLLM 博客披露，在 Hopper + FlashAttention-3 上，FP8 KV cache 曾使长上下文 needle-in-a-haystack 准确率从 91% 跌到 13%，改用两级累加策略后恢复到 89%仅摘要vLLM blog。平均基准看不到这类事故，验收必须包含长上下文检索测试。

其三，工具链完成整合。AutoGPTQ 于 2025-04-11 归档、AutoAWQ 弃用并由 vLLM Project 接手仅摘要Transformers GPTQ docs，形成"每个运行时配一个压缩工具"的格局：vLLM 配 llm-compressor，llama.cpp 配 llama-quantize/imatrix，TensorRT-LLM 配 Model Optimizer，ONNX Runtime 配 Olive，昇腾配 AMCT/Golden Stick。量化产物必须有对应的高性能内核才有意义，独立量化库因此被淘汰。格式也越来越由芯片决定：vLLM 文档写明 FP8（W8A8）只在 Ada、Hopper 及 AMD GPU 上支持一手vLLM Quantization docs，华为昇腾对 DeepSeek-V4 在 Atlas A3 上用 INT8 方案、在 950 系列上用 FP8-MXFP4 混合仅摘要，昇腾官方系列文章Bilibili 专栏。同一模型需要按芯片维护多份量化产物，目前没有跨运行时的统一量化交换格式。CSDN 博客中"显存降 60–85%、吞吐升 2–4 倍"的昇腾工具链数字属二手未验证，不宜引用为结论。

蒸馏、剪枝与低秩：只有蒸馏和 MoE 专家剪枝有实际热度

非结构化剪枝在 GPU 上性价比不成立。Wanda 仓库的 LLaMA-2 7B 结果显示，50% 非结构化稀疏使 WikiText 困惑度从 5.12 升到 6.42，而半结构化 2:4 模式升到 11.02仅摘要，经镜像站Wanda；在 4-bit 量化已能给出约 70% 体积缩减的前提下，这个代价换不来 GPU 加速。笔记没有找到非结构化稀疏在生产中获得端到端加速的公开案例。低秩分解超过约 50% 压缩比后迅速崩坏：SVD-LLM 在 LLaMA2-7B 上 40%/50%/60% 压缩比的困惑度为 16.11/27.19/89.90仅摘要，来自一份会议 slidesCVPR 2026 slides。

剪枝里唯一有热度的新方向是 MoE 的 expert pruning，llm-compressor 已把 REAP 与 MoNe 列为新特性 llm-compressor。但 LExI 论文认为 expert 剪枝主要省内存，在 vLLM 上对推理性能提升不显著，有时还因负载不均而变差仅摘要arXiv 2509.02753——省内存不等于省延迟。REAP 的原论文笔记未找到，其效果缺一手数据。蒸馏则以"蒸馏版模型"的形式广泛落地，并与量化合流为量化感知蒸馏（llm-compressor 的 QADModifier），用教师输出修复低位宽损失。

编译器退守端侧，数据中心靠手写内核

"编译"在两个场景的含义已经分化。数据中心侧，核心性能来自手写注意力与量化内核，torch.compile 与 CUDA graph 只是局部手段；引擎一节提到 "breakable CUDA graph" 在两大引擎中替代 torch.compile，vLLM 称 decode ITL 降 3.0–8.8% vLLM v0.34.0。端侧则相反，把模型下沉到 NPU/GPU 委托后端的完整导出流程是必需件，并在 2025-10 至 2026-05 之间集中"转正"：ExecuTorch 1.0 于 2025-10 发布，Meta 称其驱动的端侧功能在 Instagram、WhatsApp 等产品上服务数十亿人一手，官方博客自述PyTorch blog；Google 于 2026-01-28 宣布 LiteRT 接替 TensorFlow Lite，其上的 LiteRT-LM 支撑 Gemini Nano 的部署仅摘要，厂商自述Google Developers Blog；WebLLM 在 Llama-3.1-8B 上达到 MLC-LLM 原生解码速度的约 71%仅摘要arXiv 2412.15803。通用编译器在 LLM 上仍落后于手写实现：LLVM 2025 开发者会议的一个报告显示未调优的 IREE 跑 TinyLlama 远慢于 llama.cpp仅摘要，轶事性数据LLVM devmtg。

结构性事件是 Modular 的归属变化：Mojo 1.0 于 2026-08 发布，Qualcomm 于 2026-07-29 完成对 Modular 的收购均为仅摘要；收购消息来源为第三方 wiki 页，可靠性偏低opensourceforulatent.space wiki。一个原本"硬件无关"的编译栈归属芯片厂商后，其中立性是不确定因素（笔记作者的推断）。Modular 相对 vLLM 的性能说法均为厂商自报，没有独立基准。

架构级手段：投机解码的生产收益是 10–27%，不是论文里的 2–3 倍

投机解码的生产形态已从外挂小模型转向与目标模型共享特征的 EAGLE-3 类 draft head。Red Hat 的基准是这一层最扎实的生产口径数据：在 vLLM v0.13.0、H200 上对 gpt-oss-120b 使用 EAGLE-3 draft head，ShareGPT 负载输出吞吐提升 20.7%、峰值提升 27.2%；SWE-bench 负载下每百万输出 token 成本从 4.41 美元降到 3.56 美元（-19.4%）；但长输入负载下 TP=1 仅提升 9.5%，TP=2 时 TTFT P95 反而恶化 9.3%；draft token 从 3 增到 4 使吞吐下降 8%一手，已读原文Red Hat Developer。Berkeley 的 "Speculative Decoding: Performance or Illusion?" 在 vLLM 上做了系统研究，发现目标模型的验证主导执行时间，实测与理论上界有明显差距一手，仅读摘要页arXiv 2601.11580。DeepSeek 的 DSpark 自称最高 85% 加速，只有单一低可信度来源且无独立验证，不应采信为事实。

模型路由的节省幅度由流量构成决定。RouteLLM 在保持 GPT-4 性能 95% 的目标下，MT Bench 上成本降 85% 以上，MMLU 上只降 45%、GSM8K 上 35%；MMLU 上最好的路由器仍需 54% 的强模型调用，仅比随机路由便宜约 14%一手，2024 年数据LMSYS。2026 年博客中"企业落地节省 40–70%"的说法均为二手未验证。Early exit 与 layer skip 没有在任何主流生产引擎中启用的证据；VLM 的视觉 token 剪枝是 2026 年最活跃的研究子方向，ACL 2026 的综述把 prompt 自适应剪枝与硬件感知设计列为开放挑战仅摘要ACL Anthology。

小模型是另一条成本路径：把流量移到用户设备，或在云端用小模型承接简单请求。Google 的 Gemma 3 QAT 把 27B 模型的权重显存从 54 GB 降到 14.1 GB仅摘要，官方博客Google Developers Blog。Gemma 4 与 Qwen 3.5 小模型的规格只来自二手博客且互相矛盾，笔记未见官方模型卡，本报告不引用其具体分数。

模型层的开放问题可以归结为四条：评测方法不可靠（平均分掩盖任务级与长上下文退化）；低于 4 bit 仍需训练介入；压缩省下的内存难以转化为延迟收益；以及多种手段叠加（MoE + MXFP4 权重 + 量化 KV + 投机解码 + expert 剪枝）的复合精度影响基本没有公开研究，而这正是 2026 年生产栈的实际形态。后两条及"商业 API 是否量化不透明"是笔记作者的推断，没有直接陈述该问题的一手来源。

集群层：llm-d 与 Dynamo 两条路线定型，调度单位从请求升级为程序

三层分工确立：标准 API、调度器实现、控制面

Kubernetes 生态在 2026 年形成了清晰分工。Gateway API Inference Extension（GIE）定义推理路由的标准接口；llm-d 于 2026-03-12 被接受为 CNCF Sandbox 项目，10-20 发布 v1.0.0 CNCFllm-d releases；KServe v0.17 把基于 llm-d 构建的 LLMInferenceService 标为生产可用 KServe 0.17。决定性的一步是 GIE v1.6.0 把完整的 Endpoint Picker、Body-Based Routing 与 Latency Predictor 迁入 llm-d 仓库，调度插件此后归属 llm-d GIE releases。需要说明：GitHub release 页只显示日月，GIE、llm-d、AIBrix 各版本的年份是笔记作者根据版本依赖关系推断的；llm-d 由 IBM、Red Hat、Google 捐赠的说法来自二手报道。

另一条路线是 NVIDIA Dynamo，2026-03-12 发布 1.0 GA，支持 SGLang、TensorRT-LLM、vLLM 三种引擎，自带 KV 感知路由、Planner、KV Block Manager、NIXL 传输库、Grove 拓扑感知编排与 ModelExpress 冷启动组件一手Dynamo v1.0.0NVIDIA blog。NVIDIA 列出的生产部署方包括 ByteDance、Tencent Cloud、Meituan、小红书、CoreWeave、Together AI 等，这份名单与"Blackwell 上最多 7 倍请求"的性能口径都是厂商自述，后者绑定 DeepSeek R1、FP4、GB200 NVL72 这一具体配置。两条路线并非完全竞争——Dynamo 的 router 可以作为 Inference Gateway 的 endpoint-picker 插件运行——差别在于 Dynamo 向下绑定 NVIDIA 机架级硬件，llm-d 强调多加速器与 CNCF 中立治理。

并行的替代方案还有字节的 AIBrix（2025-02 开源，v0.8.0 于 10-13 发布）AIBrix releases、LMCache 团队的 vLLM production-stack，以及 Anyscale 的 Ray Serve LLM。各栈功能清单高度同质化：前缀/KV 感知路由、PD 分离、KV 分层、LoRA、SLO 自动伸缩。LMCache 团队"比 AIBrix 快约 10 倍"的说法是 2025-03 的厂商自测。KubeAI、Triton、BentoML、Kthena 在 2026 年的状态，笔记没有一手资料。

前缀/KV 感知路由收益最确定，PD 分离的收益依赖负载

前缀感知路由是集群层证据最硬的优化，因为有生产数据。Google 披露 Vertex AI 采用 GKE Inference Gateway 后，前缀缓存命中率从 35% 提到 70%，Qwen3-Coder 的 TTFT 降 35%，DeepSeek V3.1 在突发聊天负载上 P95 TTFT 改善 52%；其经验是必须联合调整 prefix、queue、KV 利用率三个打分器的权重，否则持有热门前缀的单节点会被压垮一手，厂商工程博客Google Cloud blog。相比之下，Google 委托 Principled Technologies 做的测试（平均 TTFT 188 ms 对 2,625 ms）使用共享前缀基准、对比对象是普通 HTTP 负载均衡，条件对前缀路由有利，应按厂商委托测试看待 PT study。路由信号本身经历了三代：网关侧近似前缀树、引擎上报的精确 KV 块事件、学习型的 predicted-latency 打分；Ray Serve 的 KVAwareRouter 在异步多轮负载上 p99 延迟最好，尽管前缀命中率更低 Anyscale。

Prefill/decode 分离已从论文变成所有主流栈的标配。DistServe（OSDI '24）与 Splitwise（ISCA '24）的头条数字属未复核，这里不引用具体倍数 DistServeSplitwise。有一手论文支撑的生产案例是 Moonshot 的 Mooncake（FAST '25）：Kimi 的 prefill 与 decode 集群分离，并用 GPU 集群中闲置的 CPU/DRAM/SSD 构建分离式 KV cache，FAST 版报告在两个集群上可多处理 115% 与 107% 的请求（arXiv 早期摘要给出的是 75%，两个版本数字不同）FAST '25。DeepSeek 在生产中使用 PD 分离的说法只有二手转述；OpenAI、Anthropic、Google 是否使用，没有任何官方表述。

2026 年的新进展在编排层：llm-d v1.0.0 的 DisaggregatedSet 把 prefill 与 decode 副本作为一个单元协同滚动升级，Dynamo 做到多模态的 Encode/Prefill/Decode 三段分离，AIBrix 用 StormService 管理多角色生命周期。难点已从"能否传 KV"转移到 P/D 配比随负载漂移、协同升级与拓扑绑定。何时值得分离没有独立界定，博客经验值彼此不完全一致：一种说法是每模型少于约 8 张 GPU 时分离只增复杂度二手rdp.in。无问芯穹的 PDD 架构自报首 token 延迟降 51.5%、单 token 成本降 37.5%，属厂商自述 量子位。

KV cache 正在变成硬件层级。NVIDIA 在 CES 2026 发布 BlueField-4 驱动的 Inference Context Memory Storage 平台（后称 CMX），定位为节点本地存储与共享网络存储之间的闪存层，自称相对传统存储最高 5 倍 tokens/s厂商自述NVIDIA newsroom。分析机构指出它需要 BlueField-4 与 Spectrum-X，而 LMCache 走标准 TCP/IP NAND Research。CMX 的实际出货与生产采用没有证据，它与 CXL 内存扩展、软件 KV 分层三条路线之间也没有独立对比基准。

调度研究转向 agent 程序，冷启动转向状态恢复

2026 年系统顶会的调度论文几乎都把多次 LLM 调用组成的程序当作调度单元。NSDI '26 的 JITServe 在执行 DAG 与调用次数运行时才知道的条件下分配"刚好够"的服务带宽，报告 goodput 提升 1.4–6.3 倍；Agentix 指出请求级与程序级的双重队头阻塞，报告同延迟下程序吞吐比 vLLM 高 4–15 倍一手，论文自报JITServeAgentix。OSDI '26 的 "Simple Is Better"（上海交大 + 阿里）主张用乘法组合取代线性加权的路由打分 OSDI '26，与 Vertex 手调三个权重的经验指向同一个痛点。工程侧同步跟进：llm-d v1.0.0 加入 program-aware fairness 与 turn-priority scoring，Dynamo 的前端接收延迟敏感度与预期输出长度的每请求 hint。

多模型共享 GPU 有一份罕见的生产数据。阿里云与北大的 Aegaeon（SOSP '25）做 token 粒度的抢占与伸缩，在阿里云百炼模型市场的数月 beta 中把所需 GPU 从 1,192 张 H20 降到 213 张（降 82%）厂商自报的生产数据；外部评论认为结果可能依赖阿里自身的软硬件栈，可迁移性未证实SOSP '25Tom's Hardware。它揭示了模型市场的长尾结构：大量模型请求稀疏，按模型独占 GPU 浪费极大。

冷启动优化从"更快加载权重"转向"恢复已初始化的进程与 GPU 状态"。Foundry 把 Qwen3-235B-A22B 的初始化从 10 分钟降到 3.9 秒论文自报arXiv 2604.06664；vLLM 自身支持 CRIU + cuda-checkpoint 的进程级 checkpoint/restore；Dynamo ModelExpress 自称让大型 MoE 加载最多快 7 倍；Cerebrium、Modal、Parasail 的"几十秒降到 2–12 秒"均为厂商自报。即便如此，缩容到零对数百 GB 的大模型仍不实用，3.9 秒只是初始化，不含调度与拉镜像（笔记作者的判断）。

多区域与容量管理方面，系统性最强的公开工作是 Berkeley 的 SkyServe（EuroSys '25），把 spot 副本分散到多个区域与云，相对纯 on-demand 平均降成本 43% arXiv 2411.01438。商业 API 把容量管理产品化为分层定价，见接入层一节。跨区域路由与 KV 亲和存在张力——把请求移到有空闲容量的区域会丢失前缀缓存——公开系统中没有看到跨区域 KV 感知路由的生产描述。

头部闭源厂商几乎不公开服务架构。少有的一手证据是 Anthropic 2025 年 9 月的事故复盘：部分 Sonnet 4 请求被误路由到为 1M 上下文窗口配置的服务器，最严重的一小时有 16% 的请求受影响，且路由是粘性的，后续请求很可能落到同一台错误服务器 Anthropic Engineering。由此可以推断其生产路由具有会话粘性并按上下文长度划分服务器池。中国厂商的披露度反而更高：Mooncake、AIBrix、Aegaeon 都同时有顶会论文与生产数据；百度、火山引擎（除 AIBrix 外）的集群调度架构则未检索到一手技术资料。

集群层的开放问题（笔记作者基于材料的归纳，不是某一来源的原话）包括：工具调用间隙期间 KV 该保留还是下沉，缺乏通用策略；多信号路由如何组合尚无共识；PD 分离的收益阈值缺乏独立界定；KV 存储层级的经济性没有独立基准；KV 格式与传输库（NIXL、Mooncake Transfer Engine、MORI-IO）尚未统一；集群调度层缺少公认的端到端 goodput 基准。

硬件层：机架成为交付单位，内存与电力取代逻辑芯片成为瓶颈

本节的笔记整体基于搜索结果摘要，多数来源是行业媒体与博客；厂商的性能与成本倍数除特别说明外均为厂商自述。

NVIDIA 用"每 token 成本"叙事卖 Rubin，AMD 以机架级产品入局

NVIDIA 已从 Blackwell（GB200/GB300 NVL72）推进到 Vera Rubin。Vera Rubin NVL72 在 2026 年 1 月的 CES 上发布，宣称相对 Blackwell 推理性能最高 5 倍、每 token 成本最低降到十分之一厂商自述Tom's Hardware。这个"10 倍"绑定在脚注条件上：Kimi-K2-Thinking 模型、32K 输入/8K 输出；有分析指出它对算力受限的 FP4 负载成立，对内存或网络受限的负载节省更小二手博客dev.to。2026 年 3 月的 GTC 上，NVIDIA 首次把专用推理硬件纳入平台：源自 Groq 授权的 Groq 3 LPU 与 LPX 机架 the-decoder。路线图上 2027 年是 Kyber 机架与 Rubin Ultra，2028 年是 Feynman；各来源对 scale-up 规模的说法有冲突（NVL576 对 NVL1152）。NVL72 整机架价格的估算同样冲突（350–400 万美元对约 780 万美元），不宜引用单一数字。

AMD 在 2026 年成为机架级竞争者。7 月发布的 Helios 机架含 72 张 Instinct MI455X、每机架 31 TB HBM4，AMD 宣称高并发下推理吞吐最高为 MI355X 的 34 倍、每美元 token 最高 18 倍厂商自述TechWire Asia。配套的是吉瓦级承诺：OpenAI 最多 6 GW（2025-10 宣布，附带最多 1.6 亿股 AMD 认股权证）Data Center Frontier，Meta 6 GW，Anthropic 最多 2 GW，AMD 称已预订约 14 GW二手iTWire。这些都是"最多"口径的承诺，截至 2026 年 11 月的实际出货量未获确认。Intel 仍在边缘：推理专用 GPU Crescent Island 计划 2026 下半年送样，没有公布任何性能数字，是否如期送样也未确认 Tom's Hardware。

相对独立的证据来自两个基准。MLPerf Inference v6.1 于 2026-09-16 发布，30 家机构、486 项结果，新增端到端 RAG 与边缘 agentic 推理两项测试，并包含 Vera Rubin NVL72 的首批经同行评审的数字（以 preview 类别提交）HPCwire/MLCommons。Rubin 的具体倍数各家表述不一——StorageReview 标题写每加速器 5.7 倍，NVIDIA 自称相对 GB300 最高 3.7 倍（Qwen3-VL）——笔记没有从 MLCommons 表格读取原始数字。SemiAnalysis 的 InferenceX 更有启发性：按其 2026 年 7 月的 TCO 假设，DeepSeek R1 在 116 tok/s/user 时 GB300 NVL72 为每百万 token 0.49 美元、MI355X 为 1.41 美元，而 MiniMax M3 在 236 tok/s/user 时 MI355X（0.34 美元）反而略优于 GB300（0.37 美元）搜索摘要中的快照值，面板每日更新InferenceXInferenceX。胜负随模型、交互性目标与每小时成本假设翻转，"最便宜的硬件"是负载相关的，不存在单一排名。

专用推理芯片被收编或上市，云厂商自研成为非 NVIDIA 的主要出货量

推理芯片创业公司在 2025–2026 年走向少数几种结局。NVIDIA 于 2025 年 12 月以约 200 亿美元授权 Groq 技术并吸纳其大部分团队（一个来源写 170 亿）二手Fortune。Cerebras 于 2026-01-14 与 OpenAI 宣布 750 MW 的多年协议 Cerebras，并在 2026 年 5 月上市；协议金额在笔记中有两个口径——Bloomberg 报道为 100 亿美元以上，Sacra 写作 200 亿美元以上——首日估值的各家数字也相互冲突，均应对照招股文件 BloombergSacra。Etched 的合同与交付数字只有博客来源，未获主流媒体确认。

云厂商自研芯片方面，Google 在 Cloud Next 2026 让 Ironwood（第七代 TPU）正式可用，并预告第八代拆分为训练用的 TPU 8t 与推理用的 TPU 8i二手The Next Web。AWS Trainium 3、Microsoft Maia 200、Meta MTIA 的规格在笔记中都来自二手博客转述的厂商说法，没有读到厂商原始页面。可以确定的方向是：Google 拆分 TPU、Intel 做推理专用 GPU、NVIDIA 加入 LPX，都指向推理硬件与训练硬件在 2026 年分化；同时头部实验室在多源采购（OpenAI 用 NVIDIA、AMD、Cerebras、Broadcom；Anthropic 用 Google TPU、AMD、AWS），同一个模型 API 之下的硬件已是异构的。引擎层对应的动作是 SGLang 通过插件支持 Google TPU7x SGLang v0.5.23。

中国：出口管制把推理推向国产芯片，约束在 HBM 与产能

内存售罄、机架走向 600 kW，瓶颈在逻辑芯片之外

内存是 2026 年最紧的供给约束。三星 CFO 据报道称全年 HBM4 产能已售罄，SK hynix 新产能要到 2027–2029 年才能放量二手IntuitionLabs；产能向 HBM 倾斜使通用 DRAM 短缺涨价 S&P Global。这直接解释了两个设计选择：推理专用芯片改用 LPDDR5X 换容量（Intel Crescent Island 160 GB），以及 KV cache 向 CXL 内存与闪存层外溢——The Register 引述的研究称把 KV cache 卸载到 CXL 内存可把 GPU 内存占用最多降 87% The Register，而 Astera Labs、MemVerge 的 CXL 数字是厂商自测。

接入层与经济性：网关被收编，有效价格下降而前沿标价上涨

2026 年网关层发生了明显的收编与基金会化。Stripe 于 2026-08-19 宣布同意收购 OpenRouter，官方称其覆盖 400+ 模型、80+ 供应商一手Stripe Newsroom；价格官方未披露，媒体口径在 70 亿到 80 亿美元以上之间不一，交割状态也有"已同意"与"已完成"两种写法二手，未经官方确认。Palo Alto Networks 于 2026-05-29 宣布完成对 Portkey 的收购 PANW；Envoy AI Gateway 于 9 月更名为 Agent Router 并加入 Agentic AI Foundation AAIF；可观测性一侧，ClickHouse 于 2026-01-16 宣布收购 Langfuse二手Towards AI。三笔网关交易对应对网关本质的三种判断：计量与计费、安全与合规、流量基础设施。阿里开源的 Higress 则把 MCP 流量治理并入网关，v2.2.4 实现了 MCP 2026-07-28 协议 newreleases。

Agent 负载有了第一批生产画像：缓存命中率是成本的决定变量

Agent 流量的占比有平台数据：OpenRouter 2026 年 10 月 agentic 流量占 token 的 76%，一年前为 8%一手，但是平台自有数据与自定义分类方法，不含 BYOKOpenRouter。最有分量的负载画像来自 Microsoft 对 GitHub Copilot 的研究（2026-06 采样，320 万用户、7.61 亿次 LLM 调用、95 万亿 token）：prompt 前缀缓存覆盖约 90% 的 token；turn 内 KV 命中率平均 90%，跨 turn 边界降到约 55%，切换模型时降到 8%；上下文压缩只在 7.8% 的会话触发，却影响 44% 的总 token，并像切换模型一样重置缓存一手，Microsoft 论文Microsoft Research。

这组数字说明路由、压缩与缓存三者互相冲突：跨模型路由把命中率打到个位数，压缩节省 token 却摧毁缓存。学术界的对应工作是 SAGA（HPDC '26），报告在 vLLM v0.6.0 上 agent 有 38% 的总时间花在重新生成工具调用期间被丢弃的 KV cache arXiv 2605.00528；Microsoft 的 SUTRADHARA 发现工具调用占首 token 渲染延迟的 30–85%，并发 agent 下与负载无关的 LRU 驱逐会使共享前缀的 KV cache 抖动 arXiv 2601.12967；Continuum/CacheTTL 按预测的工具调用时长为 KV 设置 TTL arXiv 2511.02230。这些研究多基于 vLLM 与开源模型或单一产品，闭源头部实验室的内部 agent 负载画像没有公开。

与前缀缓存相比，语义缓存的真实命中率远低于宣传：开放式聊天约 10–20%，FAQ/客服 40–70%，命中率低于约 15–20% 时 embedding 与向量查找的开销使其成为净延迟损失；厂商常说的"95%"是匹配准确率而非请求命中率二手，实践博客；没有同行评审的生产命中率研究tianpan.co。

基准的度量单位随之迁移到经济与能耗单位。Artificial Analysis 于 2026-06-12 发布 AA-AgentPerf，回放真实 coding agent 轨迹，首要指标是 Agents per Megawatt；它披露了哪些配置由 NVIDIA 提交、哪些由自己搭建，并提示后者余量可能更大一手AA-AgentPerf。InferenceX 报告 tokens per megawatt，MLPerf 正向 API 端点式测量迁移。被测对象从"芯片 + 模型"变成"端点/全栈"，结果更贴近真实成本，也更依赖厂商的调优投入。

Token 经济：降价要拆成三件事

OpenRouter 的有效混合价从 2026 年 1 月到 10 月，闭源模型由每百万 token 1.21 美元降到 0.52 美元（约 -57%），开放权重由 0.28 美元降到 0.084 美元（约 -70%）；开放权重自 4 月起稳定占 token 过半，但只占付费支出约四分之一一手，平台数据OpenRouter。另一面是标价上涨：BenchLM 的指数显示截至 2026 年 9 月的 12 个月里前沿档价格同比上涨 72%单一追踪器的方法论，谨慎使用BenchLM；摩根士丹利统计中国大模型 2026 年二季度平均 API 输出价较 2025 年一季度上涨约 80%二手转述研报澎湃。Axios 报道的两项用量加权指数下跌约 50%，笔记未能直接读取原文（403），数字来自搜索摘要。

所以"token 降价"是三件事：同等能力的价格持续下降；前沿档标价不降反升；用量加权有效价的下降主要来自结构迁移——便宜的小模型、开放权重与更高的缓存命中率（OpenRouter 的中位缓存命中率从 6 月的 76.1% 升到 10 月的 90% 以上）。长期降幅的估计相差一个数量级：一篇 2026 年 3 月的论文报告自 2020 年以来约 600 倍 arXiv 2603.28576，而归于 Epoch AI 的年降幅估计在硬件笔记中互不吻合，未对照 Epoch 原文。中国 26H1 收入增速远高于 token 增速，意味着单位 token 收入上升，与涨价及视频生成等高价模态占比提高一致。

利润分布呈两极。Anthropic 于 2026-10-26 公开递交 S-1，二手解读称上半年收入约 163 亿美元、据服务算力成本推算毛利率约 85%；但这个比例是第三方计算而非报表行项，各家解读对"S-1 是否列示毛利"存在矛盾，必须对照 EDGAR 原文二手，存在相互矛盾sec-api.io。SemiAnalysis 估算其推理毛利到 2026 年中约 70%第三方估算。另一端是硅基流动的负毛利。训练向推理的转移有多个预测口径：Gartner 称 2026 年 AI 优化 IaaS 中推理支出 233 亿美元超过训练的 190 亿美元 Gartner，Deloitte 预测推理约占 2026 年全部 AI 算力的三分之二 Deloitte；硬件笔记中也有联想 CEO"约 80% 支出在训练"的相反说法（二手）。推理与训练的划分没有公认的度量方式，任何单一百分比都要连同来源与定义一起引用。

安全与合规方面，GPU 机密计算的开销已不是主要障碍：一项研究报告在 H100 机密计算 GPU 上吞吐损失 4–8%二手，论文评述页themoonlight；障碍在于云上机型可用性与端到端可证明性，主流供应商是否已提供正式可用的 TEE 推理端点没有可靠来源。

基准与度量：负载转向多轮轨迹，指标口径仍未统一

原报告只在硬件层和接入层顺带提到几个基准。这一节是 2026-11-18 补写的摘要，细节在五篇专题里：Benchmark 总览、行业标准基准、压测工具与方法论、负载、trace 与数据集、Agent 质量基准。

基准的负载已经从单次请求变成多轮轨迹

三家有影响力的基准都在回放 agent 轨迹：MLCommons 为 MLPerf 新设了面向端点的多轮测试，SemiAnalysis 的 InferenceX 加了 AgentX，Artificial Analysis 有 AA-AgentPerf。三者都用固定并发的闭环扫描，都允许跨请求复用 KV cache，差别在档位之间怎么清缓存（盐值、重启服务、动态前缀）。MLPerf Storage 3.0 还新增了 KV cache 测试。这是两条主线在基准层的对应：被测的东西从“芯片跑一个模型”变成了“全栈服务一批会话”。

同名指标各家公式不同，数字不能跨基准比

首 token 延迟从哪一刻算起、每 token 时间含不含首 token、生成速度的分母含不含首 token 延迟，各工具各基准都不一样。Artificial Analysis 在 2026 年 11 月把输出速度改成了含首 token 延迟的口径。压测工具的官方文档承认，两个工具用默认配置打同一个服务，结果能差几十个百分点。引用任何性能数字，都要连同计时点定义一起引用。

公开的 agent 负载几乎全是编程

微软已公开 GitHub Copilot 生产 trace 的采样子集，Kimi、阿里百炼、SemiAnalysis 也有可回放的 trace。但这些都是聊天或编程负载。用聊天数据集冒充 agent 负载会系统性出错：输入短两到三个数量级，输入输出比方向相反。编程以外的 agent（文档生成、深度调查、数据分析）没有同等规模的公开画像。

质量与效率要绑在一起测

量化后通过率不变但重试变多、上下文压缩掉二三十个百分点、同一模型在不同服务商之间工具调用表现不同，都有公开报告。MLPerf 的做法是给每个性能点加精度门槛。对 agent 任务，门槛更适合写成相对于参照线的不劣于检验，并在声称的最大并发点上重跑质量评测。大型 MoE 模型在 FP8 或 4-bit 浮点下的 agent 任务质量，目前没有找到公开的对照研究。

跨层来看，有三个问题在每一层都以不同面目出现。第一是状态放在哪：agent 会话是有状态的，而弹性基础设施希望无状态。引擎层的回答是 KV 分层与 offload，集群层是会话亲和与 cache pinning，硬件层是 CXL 与闪存上下文层，协议层是 MCP 去会话化与 Tasks 句柄。这些都是局部答案，应用（何时压缩、换模型、开子 agent）、网关与引擎之间缺少传递"预期工具时长"与"缓存价值"的标准接口。第二是数字不可比：引擎横评、硬件的每 token 成本倍数、token 用量、推理占比，每一类都存在口径各异、厂商自测或条件绑定的问题，目前相对可依赖的只有披露配置来源的基准（MLPerf、InferenceX、AA-AgentPerf）与少数一手生产数据（Vertex 的命中率、Copilot 的 trace、Aegaeon 的 GPU 数、Red Hat 的投机解码基准）。第三是叠加后的正确性：量化权重、量化 KV、投机解码、专家并行与结构化输出同时启用时的行为，既超出引擎社区的测试矩阵，也没有公开的精度研究。

结论

把五层放在一起看，推理基础设施的重心已从"让一次前向更快"转到"让上下文状态更便宜地存活"。KV cache 命中率决定 agent 负载的成本——命中的前缀按大幅折扣计价，而据二手转述的 Copilot 论文数字，深度循环用户一次未命中的中位重新 prefill 约为 110 万 token Developers Digest——所以引擎的默认值、集群的路由打分、硬件的内存层级与 API 的定价结构，实质上都在围绕同一个变量做设计。谁能把"缓存价值"这一信息从应用层一路传到引擎的驱逐策略，谁就拿到了下一轮效率红利；目前还没有人做到。

第二个判断是，这个领域的知识主要存在于 release notes、厂商博客与平台数据里，而不是论文里。这带来了快速迭代，也带来了证据质量问题：本报告中相当一部分硬件、融资与成本数字只能标注为二手或厂商自述，几处关键事实（Anthropic S-1 的毛利口径、Cerebras 协议金额、Rubin 的 MLPerf 倍数、Stripe 收购价）在来源之间相互矛盾。做选型或投资判断时，建议优先复核三类原始材料：引擎与编排项目的 release notes、带配置披露的基准表格，以及招股文件原文；其余数字只宜用来判断方向和量级。
