OpenRouter

托管式模型聚合网关:一个 API、一份余额,调用 400 多个模型

与主线一 KV cache · 中自己不存 KV,但用粘性路由把会话钉在同一上游,决定上游缓存能否命中与主线二 Agent 负载 · 强流量 76% 来自 agent,路由按会话而非请求做决策,并发布 agent 占比数据

它是什么

OpenRouter 是一个托管的"模型聚合网关"。开发者只注册一个账号、充一笔余额、拿一个 API key,就能用同一套 OpenAI 兼容接口调用 400 多个模型;这些模型背后是 80 多家推理供应商(provider,即真正运行模型并出 token 的公司,如各家实验室自己的 API、云厂商、Together 这类开放权重托管商)一手Stripe Newsroom。

它解决两个问题。第一是接入:不用分别和几十家供应商签约、充值、适配接口。第二是选择:同一个开放权重模型常有十几家供应商在卖,价格、速度、稳定性各不相同,OpenRouter 替你在每次请求时挑一家,挑错了自动换下一家。它自己不运行模型,也没有 GPU,是纯粹的流量中间层。

它做了什么

计费:不加价,收充值手续费

OpenRouter 的官方说法是推理价格原样透传,"不在推理价格上加价";收入来自充值:购买余额时收 5.5% 手续费(最低 0.80 美元),加密货币支付收 5%。用户也可以自带上游密钥(BYOK,bring your own key,流量仍经 OpenRouter 路由但账单记在用户自己的供应商账户上):按量付费账户每月有 2.5 万美元免费额度,超出部分按"同模型同供应商在 OpenRouter 上正常价格"的 5% 收费一手OpenRouter FAQ。默认不记录 prompt 与输出;用户自愿开启记录可换 1% 折扣(同上)。

供应商路由(provider routing)

同一模型有多家供应商时由路由器选择。2026-10-28 之前,默认路由基本只看价格,最便宜的拿到最多流量。之后换成"Routing Cost"模型:持续测量每个端点,估算"拿到一个好回答的期望成本",综合有效价格(按实测缓存命中率和输入输出比折算)、吞吐、首 token 时间(TTFT)、429 限流率、错误率和工具调用格式是否合规;成功率 80% 的端点成本按 1.25 倍计。OpenRouter 自己做的一周交替实验(2400 万以上请求)显示 TTFT 中位数降 16.9%、遇到 429 的请求少 46%、每千次请求成本高 6%厂商自述,自有流量上的交替实验OpenRouter 博客。

用户可以用请求里的 provider 对象覆盖默认行为:order 指定尝试顺序,only / ignore 做白名单和黑名单,sort 按价格、吞吐或延迟排序,max_price 设价格上限,quantizations 限定量化精度,zdr 只走零数据留存端点,allow_fallbacks 控制是否允许换供应商;模型名加 :nitro 或 :floor 后缀是按吞吐或按价格排序的简写一手Provider Routing 文档。

模型路由与其他产品

除了"同模型选供应商",还有"替你选模型"的 Auto Router(2026-11-06 发布新版 Auto 与 Auto Code)、10 月推出的私有端点(把自己微调的模型和容量接进来)、11-10 的 Extractions API;11-16 宣布为 Hugging Face 的推理入口供货一手,仅读到博客目录OpenRouter 博客目录。

平台数据报告

因为所有流量都过它的计费系统,OpenRouter 能看到跨供应商、跨模型的真实用量。它按月发布数据回顾,也和 a16z 合作发过基于 100 万亿 token 的研究(arXiv 2601.10088,本次未打开未复核)。这些报告已成为行业里引用最多的"需求侧"数据源,但口径是它自己的:只含经它计费的流量,有效价格和缓存命中率不含 BYOK 与匿名测试模型一手October 2026 数据回顾。

2026 年的现状

  • 2026 年 10 月处理 790 万亿 token(输入加输出),环比增长 37%,约为 1 月的 25 倍一手,平台自有数据October 2026。
  • 开放权重模型约占付费 token 的六到七成,但只占付费支出的约四分之一;闭源模型的有效混合价从 1 月的每百万 token 1.21 美元降到 0.52 美元,开放权重从 0.28 美元降到 0.084 美元(同上)。
  • 收购价至今没有官方数字。Bloomberg 最初报道"70 亿美元以上",《纽约时报》口径约 75 亿美元,另有媒体写 80 亿;全部是媒体报道二手,未经官方确认Glitchwire。Stripe 的收购理由是与其已有的 Token Billing 产品结合:支付公司想要的是"token 的计量与结算"这一层。
  • 收入公司不公布,流传的数字均为第三方估算。

与主线一(KV cache)的关系

关系中等,而且是间接的:OpenRouter 不持有任何 KV cache,KV 块在上游供应商的 GPU 和存储里。但它决定请求落到哪一家,而缓存只在"同一家、同一模型、同一前缀"下才命中,所以路由决策直接决定上游缓存是否白建。

具体机制是文档里的 provider sticky routing(供应商粘性路由)一手Prompt Caching 文档:

  • 默认用"第一条 system 消息 + 第一条非 system 消息"的哈希识别一个会话,同一会话的后续请求发往同一供应商端点。
  • 没传 session_id 时,要先观察到一次缓存命中才开始粘;传了 session_id(或 x-session-id 头,或 OpenAI 风格的 prompt_cache_key)则第一次成功请求后就粘住。
  • 只有当该供应商"缓存读取价低于普通输入价"时才启用;会话闲置 60 分钟过期;按账户、模型、会话三个维度记录。
  • 用户手工指定了 provider.order 时不启用粘性;粘住的供应商不可用时自动回退到次优者,此时上游缓存等于丢失,要重新预填充。

换模型同样丢缓存,这是模型不同、KV 不通用决定的,网关无法弥补。Microsoft 对 GitHub Copilot 的研究给出量级:KV 命中率在一个 turn 内平均 90%,跨 turn 边界降到 55%,切换模型或压缩上下文后被"大幅作废"一手,仅读到摘要Microsoft Research。

新路由器把缓存算进了价格:有效价格按实测缓存命中率计算,供应商不能靠"输入标价低、缓存 token 收费高"骗到流量。平台数据显示,10 月多数供应商对 agent 流量有 85% 到 97% 的 prompt token 走缓存前缀,中位命中率从 6 月的 76.1% 升到 90% 以上一手,平台自有数据,仅统计 agentic key 且不含 BYOKOctober 2026。这是目前少有的跨供应商缓存命中率公开数据。

与主线二(Agent 负载)的关系

关系强,体现在三处。

  • 数据:OpenRouter 称 2026 年 10 月 agent 流量占全部 token 的 76%(约 600 万亿),一年前为 8%。分类方法是给每个 API key 按 7 个加权信号逐月打分,0.50 以上算 agentic,0.25 到 0.49 算混合,以下算人工一手,但分类方法为平台自定义,七个信号的细节本次未读到October 2026。这是"agent 已成主要负载"最常被引用的证据,但只代表聚合平台上的付费 API 流量。
  • 路由单位:粘性路由意味着只有会话的第一个请求是算法选的,之后整段会话钉在同一供应商。路由的决策单位从"请求"变成了"会话"。
  • 指标权重:新路由器重罚 TTFT 和 429,官方给的理由是 agent 会话里模型连续发起多次工具调用,每一次都要等首 token一手OpenRouter 博客。

与图中其他概念的关系

  • LiteLLM:同层的另一种形态。OpenRouter 是托管服务,密钥、账单、路由都在它那里;LiteLLM 是自己部署的开源代理,密钥和日志留在自己手里。两者可以叠用,LiteLLM 可以把 OpenRouter 当作一个上游。
  • Open Responses:报告笔记称 OpenRouter 是该规范 2026-01 的首批伙伴之一未复核,本次未打开规范站点。
  • MCP:OpenRouter 博客有 MCP 相关教程,但本次没有核实它是否提供 MCP 网关,不作断言。
  • vLLM / SGLang 等引擎:OpenRouter 上的开放权重供应商在后端运行这类引擎,粘性路由要保护的就是这些引擎里的前缀缓存;OpenRouter 与引擎之间没有直接接口。
  • AA-AgentPerf:两者从两端描述同一件事。OpenRouter 的数据说明需求侧 agent 占多数,AA-AgentPerf 在供给侧用 agent 轨迹测硬件。
  • Cerebras:作为供应商之一出现在 OpenRouter 上未复核。

存疑与未核实

  • 交割状态:报告写"交割状态有两种写法"。现状是 11-10 交割完成的报道一致,但我没能直接打开 Stripe 的 X 帖子,Stripe 新闻稿页面仍只有 8-19 的"同意收购",OpenRouter 公告页"最后更新"仍为 8-19。交割一事标为二手。

  • "不加价":是官方自述;路由到哪家、是否命中缓存都会影响实际花费,5.5% 充值费实际上就是它的抽成。
  • 用户数有 800 万(5 月,TechCrunch 转述)和 1000 万以上(8 月,官方公告)两个数字,时间不同,不矛盾。
  • 创始团队其他成员、a16z 合作研究的细节、收入数字,本次均未从一手来源核实。
